Wrapped Codex CLI (codex-cli 0.150.x) via `codex exec --sandbox read-only -`:

- The captured output ECHOES the entire prompt+payload first (banner, `user` block, session log), then a `codex` marker line with the final message, then `tokens used`, then the final message REPEATED. Parse the tail (last occurrence), not the head.
- Appending `| tail -c 6000` to the codex command does NOT shrink what the Bash tool captures — the echo/session log goes to stderr, which the tool merges into the result regardless. Persisted tool-results file is ~3-19x the payload (98 KB diff → 307 KB; 74 KB → 346 KB; 47 KB → 358 KB; 20 KB → 282 KB; 16 KB → 302 KB when codex does many rg/sed cross-reads; 7.4 KB → 83 KB, 2026-09-02); just `tail -c 6000` that file in a second call to reach the verdict. Verified eight times, back when payloads still included a diff (see superseded-transport note below — a scope manifest is far smaller, so this multiplier matters less now, but the "parse the tail of the persisted result" mechanic still applies). (This is the Bash tool's own internal result buffer, not a file this agent writes — no contradiction with the no-file-output contract below.)
- Session log may contain scary-looking ERROR lines — codex's own plugin/skill loading (pwsh CreateProcess 1920 inside its sandbox reading `~/.codex/plugins`), `codex_core::session: failed to record rollout items: thread ... not found` right after the final message, an `rg: ... (os error 123)` from a malformed cross-read glob, or — when codex decides to run `node tests/run.js` itself — `FAIL ... EPERM: operation not permitted, mkdtemp ... asd-sync-test-XXXXXX` with `30/83 passed`. All non-fatal noise: the tests fail only because the read-only sandbox blocks temp-dir creation; cross-check against the sprint's latest impl-test decisions-log entry (83/83 at HEAD) rather than treating it as a finding. The review still completes and the final message is emitted (and repeated after `tokens used`).
- **SUPERSEDED transport, kept only as a historical note — do not use**: earlier dispatches piped a live `git diff` on stdin — `{ cat <<'PROMPT_EOF' ... PROMPT_EOF; git diff <sha>...HEAD <pathspec>; } | codex exec --sandbox read-only -`. That construction is retired. `external-review.md` "Phase-scoped payload" is unambiguous and is the SSoT: this agent is handed a **scope manifest** (`files[]`/`exclude_paths[]`), never a rendered diff — the wrapped CLI resolves `files[]` content itself, from the repo, via its own read-only tools, never from bytes on the manifest. Never fall back to a diff pipe, including as a workaround for anything. What still holds from that era, and is load-bearing: the no-disk heredoc/here-string-to-stdin mechanics themselves — prompt + scope manifest concatenated on stdin in one pipe, e.g. `{ cat <<'PROMPT_EOF' ... PROMPT_EOF; cat <<'MANIFEST_EOF' ... MANIFEST_EOF; } | codex exec --sandbox read-only -`. Nothing pre-written to scratchpad, not even for size-checking — use `wc -c` on a pipe instead. This "no file writes at all" rule covers the CLI's stdout too, not just the prompt/manifest going in — see "Foreground, bounded timeout, stdout capture only" below; a prior version of this entry wrongly endorsed redirecting codex's own output to a scratch file. See [[scope-manifest-transport]] for the manifest contract, cost profile, and cache/failure details.
- `--sandbox read-only` accepted and honored (banner confirms `sandbox: read-only`); model resolved to gpt-5.6-sol, high reasoning; ~53-145k tokens for a 7-156 KB payload, well under the 600 s timeout.
- Prompt tail that yields clean output (2026-09-02): append "Use severity terms: blocker | critical | major | minor | info. Give each finding an id (F1, F2, ...). Cite file:line from the NEW side of the diff. You may read repo files for cross-reference (read-only sandbox). Output only the verdict block as your final message." → codex returns exactly the template's verdict block with `F<n>:` prefixes in descriptions, no prose wrapper. Asking for a trailing `dropped_below_floor: <n>` line instead of listing sub-floor findings works and gives the dropped count for free. Asking for trailing `P<n>: resolved|carry-over|partial — <one sentence>` lines per prior finding also works cleanly and gives the stalemate input directly. Also worth stating explicitly in framework mode what counts as "code" (rules/agents/workflows/manifest) and that cross-file contradictions/dangling refs/unsatisfiable obligations are defects — it then cross-reads unchanged files (e.g. setup skills, `sprint-lifecycle.md` writer rules) for gaps, which is exactly what the internal reviewers miss.
- Iter 2+: paste the prior finding set inline with "verify fresh, do NOT assume fixed" — codex then re-checks unchanged files outside the incremental diff and catches carry-overs (e.g. a `core.md` finding the fix round never touched although decisions-log claimed it resolved; a "Recording scope" clause that names an action no permitted writer performs; a 3-skill Skip-removal fix that landed in only 2 of the 3 skills). Cross-check decisions-log "resolved"/"affected docs" claims AND the dispatcher's own resolution summary ("Skip now removes the section in all 3 skills") against the actual diff hunks per file — both can overstate; a one-Grep-per-file check on the claimed change is cheap and caught a miss in iter 5. When the dispatcher pre-announces an accepted resolution shape (e.g. "removed from 4 agents instead of adding to 11", "amend rule instead of splitting entries", "drop the unreachable branch", "key guards on own-file existence + force-include in edit mode"), say so in the prompt with "do NOT re-flag the shape itself" — codex honors it and verifies consistency instead of re-raising.
- Seeding concrete "check whether X" questions in the prompt (e.g. "does Skip leave a placeholder section on disk?", "could a stale/partial file cause a wrong branch with data loss?", "does Edit mode's force-include actually route a missing file into the right phase loop?") reliably gets them checked, but codex tends to rate a seeded confirmation one tier too high (`major` for a wording gap; `critical` for a data-loss path whose precondition is the user manually deleting a file the skill itself wrote earlier). Calibrate against how the internal reviewers rated the PARENT defect in the prior iteration (e.g. iter-4 quality rated the always-reachable skeleton-overwrite `high`, so a narrower residual of it cannot honestly be `critical`); keep the finding at the calibrated tier, and when that drops it below a `critical` floor, still surface it in a "below-floor, cheap fix" note so PM can overrule.
- Codex re-litigates deliberately-scoped design choices (e.g. an agent's gate table intentionally narrower than `checkpoints.md`, with an explicit pointer). Before keeping, read the cited spot + the sprint decisions-log/plan for a recorded rationale; if the choice is documented and nothing dangles, drop as nitpick and note it so PM can overrule. A rationale that lives only inline in the mirror file (not in the SSoT rule it contradicts) does NOT count — that is still a cross-file contradiction.
- Codex line-number citations were exact in every run so far but can be off by a few lines — always verify the cited location with Grep/Read before keeping a finding, and cite the verified line.
- Grep tool: a brace glob like `{asd-concept,asd-stack}/SKILL.md` with `path` set to a parent dir returned no matches — and the `glob` parameter with a brace list (`{rules/*.md,templates/t_x.html}`) ALSO silently returns "No matches" even when the files contain the pattern (2026-09-02). Use one Grep call per file with `path` = the file instead. A single negated glob `!**/sprints/**` with `path` = `.asd` works fine for repo-wide token sweeps.
- This repo is self-hosting: impl-review pathspec is the `self_hosting: enabled` row of `external-review.md` § Phase-scoped payload (excludes `.asd/project/**`, `.asd/sprints/**`, generated views) — NOT the consumer `':(exclude).asd/**'` row.
- Iteration 2+ diff base: `state.json.reviews.impl.iteration_heads["iter-(N-1)"]` (rule changed sprint 002 iter 3; was "last commit only"). Prior finding set arrives inline in dispatch payload — never read prior `iter-*/` files even if the dispatcher's message suggests it.
- Stalemate test is "identical issue set (same files, lines, messages)". A partial fix that moves the defect to a new clause/line with a narrower message, or that lands in 2 of 3 target files, is a carry-over, NOT a stalemate — report it as a kept (or below-floor-noted) finding and say explicitly which part of the prior finding remains, so PM can judge. Two consecutive APPROVEs with the prior iteration's below-floor notes now verified resolved (iter 5 → iter 6, sprint 003) is convergence, not stalemate.
- Verifying a "reach carve-out" fix (a branch/bullet claiming its own scope narrower/wider than its enclosing header): check the reach statement sits on the SAME line as the SSoT citation in every mirror file, not just present somewhere in the section — a fix that states reach elsewhere in the block still leaves the acting bullet ambiguous on its own. Sprint 009 iter-4: "Late duplicate return — applies to any replaced dispatch, External Review included:" landed on the same line as `per review-policy.md "Late duplicate return" (sole SSoT...)` in both asd-phase-design-review.md and asd-phase-impl-review.md — genuinely closed the iter-3 finding, confirmed via direct grep of both files plus a wrapped codex pass (APPROVE, dropped_below_floor: 2).

## Foreground, bounded timeout, stdout capture only

Run the invocation as a normal foreground Bash call (not `run_in_background`) with a bounded tool
timeout (600000ms observed sufficient up to 659 KB captured output). A prior sprint 010 dispatch died
because a background-launch attempt was killed with its parent turn, not because codex itself was
slow — foreground-and-await is what fixes that, never a disk hop. Capture stdout/stderr directly as
the review text (`2>&1`, merged into the same captured stream); do not redirect codex's own output to
a file, even a scratch one deleted immediately after reading it back. This agent's contract is
"no file writes at all" and "no temp file, no cleanup step needed since nothing was created" — that
covers the CLI's own stdout, not only the prompt/scope-manifest going in. On an interrupted turn,
re-run the invocation clean rather than adding a redirect-and-delete workaround.
