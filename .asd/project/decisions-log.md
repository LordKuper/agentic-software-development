The rename is reference-only in this repo — no `design/` folder exists on disk here, since `documents.prd`/`ux_spec`/`adr`/`c4` are disabled in the lean self-hosting profile.
- **Affected docs**: `.asd/sprints/001-rename-design-to-docs/sprint.md` (AC-1…AC-8 — the acceptance-criteria source of record for this sprint, since `documents.prd` is disabled), `.asd/sprints/001-rename-design-to-docs/state.json`. ## 2026-09-01 — Sprint 001 audit approved; consumer migration documented-only, AC-7 made verifiable

Two escalations resolved and folded into `sprint.md`: (1) **R-13** — consumer migration takes the **documentation-only** path (option a): new **AC-9** requires a `CHANGELOG.md` entry documenting the breaking rename and the consumer steps (`git mv design docs`, update `commands.yaml` `designmd-*` aliases, then `/asd-update` followed by `/asd-sync`). AC-7's original wording ("no remaining reference … spelled `design/`") had no mechanical test — a bare grep returns ~180 legitimate out-of-scope hits (G-7) and is separator-blind, missing 4 real Windows-path occurrences in `t_commands.yaml:21,23` and `asd-init/SKILL.md:101,103` (R-10). Also carried into plan: `--apply` must be passed explicit file lists per touched target (G-9), and a final `--apply` is mandatory so `upstream_hashes` are not shipped stale, which would otherwise make consumers silently *skip* the renamed rules (R-12).

## 2026-09-01 — Plan approved for sprint 001-rename-design-to-docs

- **Decision**: Approved `plan.md` for sprint `001-rename-design-to-docs`: 11 tasks, `backend-dev` owner throughout (prose/config/markdown infrastructure, no UI). Decomposition is one task per canonical directory (`.asd/rules`, `.asd/templates`, `.asd/agents`, `.asd/skills`, `.asd/workflows`, `.asd/project`), plus CHANGELOG (Task 7), README + AGENTS mirrors (Task 8), provider-view regeneration (Task 9), manifest ledger recompute (Task 10), and final verification (Task 11). Mandatory ordering baked into Dependencies: all canon edits (1–8) → per-file `sync.js --apply <file...>` (9) → bare `sync.js --apply` for the ledger (10) → the AC-7 greps (11). Two sub-decisions taken here: (a) **file ownership stays one-file-one-task** — the three cross-cutting atomic sets (R-4 `':(exclude)design/**'` pathspecs, R-10 backslash `design\\ux\\DESIGN.md` aliases, G-1 prose reword) are subtasks inside their owning file-group task, with integrity guaranteed by targeted `exclude)design` and `design\\ux` greps in Task 11, rather than being split into separate tasks that would put 5 files under joint ownership; (b) **the AC-9 CHANGELOG entry is authored now, in impl, under an `## Unreleased` heading**, and the `pr` phase only renames that heading to the concrete version alongside the `asd_version` bump. Stub-inclusion step was a no-op — `.asd/project/stubs.md` holds only the placeholder row and `audit.md`'s "Related open stubs" section confirms none.
- **Rationale**: The sprint's danger is not build breakage but silent partial success — audit R-11 established that a half-renamed tree yields green `sync.js --check`, green `tests/run.js`, and a freshly rewritten manifest ledger simultaneously, because `--check` has no targets under `.asd/rules|templates|workflows` (G-10), `tests/run.js` has no `design` fixture, and a bare `--apply` writes zero targets (G-9). The plan therefore encodes the sequencing as hard dependencies and makes the two AC-7 greps the sole completeness gate, run last. Per-file subtasks carry audit.md's exact line numbers plus explicit do-NOT-touch lists, because ~180 of the 426 raw hits are out-of-scope exclusions that frequently share a line with in-scope refs (R-1) — no global regex replace is permitted. Splitting the atomic sets into their own tasks was rejected: it would trade a low, line-level consistency risk for joint ownership of 5 files across parallel devs. Authoring the CHANGELOG in impl rather than deferring to `pr` closes AC-9 inside the phase that owns it and removes any contention between `impl` and `pr` over the same file.
