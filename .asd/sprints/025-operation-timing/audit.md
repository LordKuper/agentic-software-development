## Risks
- Clean-tree checks fail on ledger writes made between commits: impact=sprint blocks (impl-review entry check sprint-lifecycle.md:46 / asd-phase-impl-review.md:7; impl-test "porcelain MUST be empty" asd-phase-impl-test.md:59; impl authorised-path gate asd-phase-impl.md:100; next sprint start on the post-PR tail git-strategy.md:78, asd-sprint:43, asd-phase-scope.md:5), mitigation=one exclude pathspec at each check (`':!.asd/sprints/*/timing.jsonl'`), ledger listed as orchestrator bookkeeping (git-strategy.md:43), closure write commits the tail; these edits touch gates, so those Tasks route `critical`.
- The model forgets a mark: impact=unpaired or missing operations skew totals, mitigation=the summary reports ledger gaps (close without open, operation outside a phase, still open) so retro can raise an F-N.
- Test determinism: impact=flaky or §17-banned tests, mitigation=pure `mark(ledgerText, events, now)` and `summary(ledgers)` tested on fixed fixtures; CLI tests assert ISO shape and pairing, never values, never sleep.
- Windows PowerShell vs Git Bash: impact=broken command lines (Codex runs PowerShell on win32, external-review.md:11; PowerShell 5.1 has no `&&`), mitigation=no chained `&&`, no JSON on the command line, quote ids with spaces, comma lists (parseFlagArgs drops repeated flags).
- Concurrent appends (parallel Bash calls, tester): impact=interleaved lines or duplicate ids, mitigation=one `appendFileSync` per call with all lines joined; caller-supplied unique ids; only phase ordinals computed (phases never overlap); recovery reads then appends only at resume, when nothing is in flight.
- Clock source: impact=negative or odd durations, mitigation=only the runtime's system UTC clock and git commit dates, never model-written times; summary clamps a negative duration to 0 and flags it.
- Failure handling vs AC-4: impact=a non-zero exit may halt the model while swallowing breaks code-style §6, mitigation=on write failure print a stderr warning and exit 0; log one F-N per sprint.
- Claude permission prompts: impact=extra prompts in the 8 phase skills without `Bash`, miscounted as machine time, mitigation=add `Bash(node .asd/runtime.js:*)` to their `allowed-tools` (canon hashes change); Codex approvals outside ASD's control.
- Too many slow flags: impact=retro token cost grows, mitigation=cap the slow set (top K by excess), summary emits the excess so the expected saving is computed, not guessed.
- No timing data for sprint 025: impact=its own retro shows "no timing data", baselines arrive late, mitigation=expected; state it in CHANGELOG.
- update.js `get` throws inside the `error` listener (:443): impact=uncaught crash offline, hits `/asd-update` today and would hit the check; no timeout, unbounded redirects, mitigation=fix once at the shared root — reject on error, timeout, redirect cap.
- Proxy networks: impact=Node https ignores `HTTPS_PROXY`, check reports unreachable, mitigation=warn and continue (tarball fetch has the same limit today).
- Private, forked or non-GitHub repo: impact=404 or `parseRepo` throw, mitigation=treat as unreachable and warn, never fail.
- Untrusted remote data: impact=acting on injected content, mitigation=read only `asd_version`, validate `^\d+(\.\d+)*$`, ignore the rest.
- Partial update (migration failure records the reached version, conflicts skipped): impact=dirty sprint branch on a mixed version, mitigation=report, then request user decision — continue on the reached version committing what landed, or abort; `asd-update` has no rollback.
- Stale definitions after an in-session update: impact=stale agents/skills on Codex (unverified) or in a newly created directory on Claude, mitigation=`sync.js --apply` in the flow; on Codex consider halting with "restart, then `/asd-sprint`".
- Raw CDN caching: impact=a release bump may appear minutes late, mitigation=none needed.
