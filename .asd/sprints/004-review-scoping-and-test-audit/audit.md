## Existing implementation found **[Architect]**

**Suite / cycle mechanics (AC-1/AC-5)**

- Test runs exist in exactly one place: `asd-phase-impl-test.md` step 7 — `asd-test-engineer` runs `commands.yaml` `test`, then `lint`, `build`, and writes the raw result plus the `HEAD` sha into `test-plan.md`'s `Suite run`. Verdict read from exit code + report, never an agent summary.
- The result is read later in exactly one place: `asd-phase-pr.md`'s gate, a *content-scoped* check — `git diff --quiet <recorded HEAD>...HEAD -- . ':(exclude).asd/sprints/**' ':(exclude).asd/project/**'`; empty diff → trust the recorded pass, non-empty → re-run `test`+`lint`. Its justification asserts "impl-review produces no code/test/stub changes … so it never invalidates this."
- `impl` never runs tests: step 9 completion gate is build+lint only ("tests are NOT run here — the suite is the `impl-test` gate"). Devs write production code only.
- `impl-review` runs no commands except `git diff`/`git show` (step 1); reviewers are read-only at host level.
- Routing state: `state.json.review_fixes_pending` (`"iter-NN"`|null) and `test_defects_pending` (bool|null). impl detects mode from these two; impl-review sets the former via PM → `NEXT: impl`; impl-test sets the latter inline → `NEXT: impl`; impl clears whichever it entered on. impl always exits `NEXT: impl-test`; impl-test exits `NEXT: impl-review` on green.
- `impl-test` re-entry scoping already exists: `Entry log` rows with `HEAD analysed`, delta = `git diff <prior-sha>...HEAD`, written after the author commit — but the doc states three times that this scoping applies only to analysis passes, never to the suite gate.

**Fan-out mechanics (AC-2/AC-3/AC-7)**

- impl-review step 6 dispatches seven internal reviewers + `asd-external-review`; design-review step 7 dispatches documentation + simplification (always) + ui (conditional on ux-spec/design-system in the draft set) + external.
- Two diff-derived skip predicates live in `asd-phase-impl-review.md` step 5 (declared sole SSoT): UI-surface predicate (extension/path-segment list, with a self-hosting carve-out for `.asd/templates/*.html`); Performance predicate (conjunctive: no perf-budgets section AND no executable file in scope). Gated on `review.scoped_fan_out` (absent = disabled = full fan-out). A skipped reviewer gets `verdicts["iter-NN"].<key> = "skipped: <predicate>"` and no review file.
- Verdict parsing: step 8 parses the first-line token from the *written* files; skipped keys were written at step 5. Satisfied-vs-blocking semantics delegated to `sprint-lifecycle.md` "State recovery".
- Coverage-ledger gate (step 7): validates each internal reviewer's ledger covers every file in the scope list, no blank/unresolved row; failure → reject + re-dispatch fresh, same iteration. External Review exempt. Only ledger-complete reviews are written, in reduced form.
- `state.json` shape: `reviews.design = {iteration, verdicts}`; `reviews.impl = {iteration, verdicts, iteration_heads}`. Verdicts keyed `"iter-NN"` → `{<reviewer-key>: <token|"skipped: …">}`; reviewer keys are the short names.
- File naming: `<sprint>/reviews/{design|impl}/iter-NN/<reviewer>.md`. The workflow writes them; reviewers return text only.
- Counter lifecycle: both counters start at 0, increment at each phase entry; on rollback to a phase earlier than the review's input-producing phase the counter resets, severity floor resets, `verdicts` clear. This is the existing hook AC-2 names for latch reset.

**Update/sync machinery (AC-11/AC-12/AC-13)**

- `update.js` pulls via `buildFileUniverse` = union of every real file under `managed_paths` of the old (local) and new (upstream) manifests; `classifyAll` hashes local + upstream and consults `oldManifest.upstream_hashes[relPath]`; `sync.classifyUpdateItem` decides `add | update | delete | noop | conflict | conflict-foreign | keep-local-modified | foreign | reject`. `applyClassifications` writes add/update (+ forced conflicts) and `fs.rmSync`s `delete`.
- **A consumer's installed ASD version already exists**: `release-manifest.json.asd_version` (currently `3.1.0`). `planUpdate` returns `{oldVersion, newVersion}` — read and reported, never used for branching. Written by `writeUpdatedManifest`, which copies the whole new manifest and only overrides `upstream_hashes` — the version advances in one atomic jump at the end of `applyPlan`, after all file writes, before `sync --check`. `config.yaml` holds no version field.
- `sync.js --apply` on a **deleted** canonical source: nothing happens. `buildSyncPlan` is source-driven — it reads the canon directories and emits targets from what exists, so a deleted canon file produces no plan item; `runCheck` never reports the orphan and `runApply` can never delete it. A **rename** is add-new + silent orphan of both generated views. Deletion is manual today.

## Gaps **[Architect]**

- No suite/impacted distinction anywhere. Every current statement is binary "full suite" — impl-test step 7 and its Re-entry section ("stays full and unconditional on every entry"), impl-review's preconditions, and the `Suite run` pass precondition. The impacted-set definition AC-5 wants in `sprint-lifecycle.md` does not exist in any form.
- No test execution step exists at the end of `impl-review`. Its "Operations used" lists only `git diff`/`git show`, and "Agents delegated to" is reviewers + PM with an explicit "No devs". Dispatching the test agent from impl-review is a new capability, and the "impl-review produces no code/test/stub changes" invariant — relied on by the pr gate and impl-test's precondition text — breaks the moment a red-suite test-defect fix happens there.
- pr-phase gate is safe but under-specified for the new topology: it reads `Suite run`'s `HEAD` (unchanged per AC-5) but its justification sentence about impl-review not touching code becomes false; the diff-based fallback still protects correctness — a wording gap, not a logic gap.
- No latch storage or read. `reviews.<phase>` has only `iteration`, `verdicts`, `iteration_heads`; no workflow filters dispatch by prior verdicts. A latch needs a new persisted key, a dispatch filter in two workflows, and an aggregation rule treating a latched reviewer as satisfied — `sprint-lifecycle.md` "State recovery" must gain the latch value alongside `"skipped: …"`.
- No sprint-wide latch-clearing hook. The existing reset is rollback-triggered only. A red full suite at the end of impl-review routes to `impl`, which IS earlier in the chain than impl-review's input-producing phase — confirm in plan whether the existing rule already clears, or whether AC-2 needs its own explicit invalidation clause.
- No change-surface rule in `review-policy.md`. Diff scoping exists operationally (step 1 diff, step 6 scope list, step 7 ledger gate) but no stated rule that a finding about unchanged code is invalid.
- No `.asd/migrations/` tree, runner, ordering logic, or version comparison. `planUpdate` reads both versions and branches on neither; `applyPlan` has no hook between file writes and `writeUpdatedManifest`. AC-12's per-migration version recording conflicts with `writeUpdatedManifest`'s all-or-nothing whole-manifest copy — that function needs a version-override parameter or a split write.
- `sync.js` has no orphan detection at all. AC-14's "confirm it removes or reports the orphaned generated view" resolves to: it does neither. Nothing enumerates the generated trees to compare against canon.
- `managed_paths` does not include `.asd/migrations` — without adding it, migration scripts never reach a consumer and the mechanism cannot bootstrap itself. It also excludes generated provider trees, which is *why* AC-13's cleanup migration is needed: `update.js`'s `delete` classification can never remove an orphaned `.claude/agents/asd-backend-dev.md`.
- No affected-test-selector field in `t_commands.yaml`, and `asd-init` step 8 detects command strings, not runner flags. Populating a `--changedSince`-style field needs new detection logic keyed on the detected runner plus a new line in step 8a's proposal.
- **Consistency gaps.** Retired names appear beyond the AC-14 touch list: every reviewer `description` cross-names the others as delegation targets (a five-way rename touches all seven files, incl. both survivors); `asd-reviewer-documentation`'s description names the ux agent; both dev descriptions name each other, the test agent, and the ux agent. `t_commands.yaml`'s header names three retired agents. `asd-phase-impl.md` parses the literal owner tokens `backend-dev`/`frontend-dev` from `plan.md`.

## Risks **[Architect]**

- Full-suite move to impl-review breaks the phase's read-only-ness: impact=the pr gate's "impl-review never changes code" justification and impl-test's precondition text go stale, and a test-defect fix inside impl-review can invalidate the very iteration just approved; mitigation=confine the suite step to a terminal, post-all-APPROVE position; on any red, exit the phase rather than fixing in place, and restate the pr gate's justification in terms of its diff check, which is already sha-independent.
- APPROVE latch masks regressions from later review-fix commits: impact=a reviewer that approved iteration 1 never sees iterations 2+ fix commits, so a fix can regress its domain silently; mitigation=AC-2's red-full-suite invalidation is the only backstop, so it must clear latches sprint-wide (not just the failing reviewer), and the latch must be stored per phase per reviewer key so the rollback reset already clears it.
- Impacted-set derivation is search-based and can under-select: impact=a missed dependency edge means a real regression is not run until the single end-of-cycle full suite, late in the cycle; mitigation=the shared-infrastructure safety valve must be mandatory and checked before *every* scoped run; in this repo nearly every canonical edit is framework-wide, so the valve fires often — verify the degradation path is cheap, not that it is rare.
- Five→two reviewer merge silently drops rubric items: impact=coverage regression invisible to the ledger gate, which validates *file* coverage, not *rubric* coverage; mitigation=the merged agents' ledger must enumerate rubric sections as rows (including `n/a: <predicate>` rows), so a missing section is a blank row the step-7 gate already rejects.
- Rubric-section skip weakens the cost saving the predicates bought: impact=the merged agent is always dispatched, so the skipped domain's context load returns even when the predicate says nothing to review; mitigation=keep predicate evaluation in the workflow and pass the `n/a` verdict into the payload, so the agent never loads that domain's inputs.
- Cross-phase promotion of impl-only rubrics: impact=`correctness` in design-review could emit code-level findings against drafts (no code exists yet), `efficiency` could apply perf budgets to prose; mitigation=design-review payload carries an explicit allowed-section list, mirrored in `review-policy.md`'s DoD table rather than left to the agent body.
- Migration mechanism runs before the code that defines it: impact=migration scripts arrive in the same `update.js` apply they are meant to sequence against, so a runner invoked from the old `update.js` may not see them — exactly the trap `loadFreshSync` already solves for `sync.js`; mitigation=load the migration runner from the freshly written tree the same way, with sequencing (after file replacement, before `writeUpdatedManifest`) fixed explicitly in plan.
- Partial-migration version recording contradicts the atomic manifest write: impact=stop-on-failure leaves files half-migrated while `writeUpdatedManifest` either already jumped the version or never wrote it — both violate "never left at an unrecorded intermediate version"; mitigation=resolve AC-12's open decision first and make the version write a distinct per-migration operation, not a side effect of the manifest copy.
- Cleanup migration deleting generated views is destructive and outside `managed_paths`: impact=a path-construction bug can remove a consumer's custom `.claude/agents/*.md`; mitigation=delete only an explicit hardcoded list of the nine retired names, verify the ownership marker before removing, treat a missing file as success.
- `sync.js --check` cannot prove the cleanup worked: impact=AC-15's "zero dangling references" is verifiable only by grep; mitigation=treat the repo-wide grep as mandatory manual verification, and consider adding an orphan-detection assertion to `tests/run.js` beside the existing roster tests so the invariant is enforced going forward.
