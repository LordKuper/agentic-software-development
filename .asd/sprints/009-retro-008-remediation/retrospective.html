Retrospective — Sprint 009 · retro-008-remediation

6 entries · 9 actions · 6 systemic proposals · updated 2026-09-09

Outcome

6 entries analysed, 1 consumer action, 8 framework actions, 6 systemic proposals.

This sprint remediated the sprint 008 retrospective and, in doing so, ran into four of the classes it was remediating — while the rules that fix them were still being written. Three of the six entries (F-1, F-2, F-3) are parallel-dispatch collisions in the first implementation wave, the one wave that necessarily executed under the pre-fix rule. That is not bad luck: a sprint whose deliverable is a dispatch contract cannot adopt that contract until the task landing it completes.

The machinery that did exist worked, and the record should say so. F-4 is External Review returning an availability skip instead of nothing — the outcome contract this sprint added, exercised on its first real failure. F-5 was caught because the orchestrator read a fix round's diff before committing it; the assertion the interrupted tester had just written was itself the tripwire, and the suite was red, not green, in that state. The sprint cost five review iterations, four fix rounds and roughly thirty-six findings, and closed with the suite at 171 tests, up from 160.

F-1A sprint that remediates a dispatch rule executes its first wave under the pre-fix rule, because the task landing the rule is itself in that wave; nothing orders a contract-changing task ahead of the tasks dispatched under it.asd
F-2Staging discipline assumes every action can be path-scoped, but some verification commands are inherently whole-tree — git add --renormalize . has no form that answers the same question about one path — so the rule cannot cover the very commands most likely to sweep a sibling's work.asd
F-3Commit ownership is bound to authorship, and two concurrent agents writing one memory file each correctly avoid committing the other's in-flight edit — so a co-authored file is structurally ownerless. AC-13b assigned an owner for the reviewer case only, where the author holds no commit tool at all.asd
F-4Preflight is defined to predict only local executable and auth state, never paid-request availability, and no cheaper signal exists — so a provider whose quota is exhausted is discovered only by spending the dispatch, at whatever iteration that happens to be.asd
F-5The fail-first proof obligation requires mutating a file the agent does not own and restoring it afterwards, with no crash safety between the two steps and no exit check that a fix round's diff is confined to paths its agent was authorised to touch.asd
F-6The coverage-ledger enforcement paragraph collapses two different failures — evidence that is incomplete, and evidence that is complete but in the wrong container — into one response, so a formatting slip costs the same full re-dispatch as an unfinished review.asd
