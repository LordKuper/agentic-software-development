## Gaps

- **AC-1 — no staging-ownership statement exists anywhere.** `git-strategy.md:39` states only the negative commit half; nothing states the positive commit half or the staging half. **Single home: `git-strategy.md` "Commit before review" (`:33-39`)** — append to `:39`'s paragraph. `asd-phase-impl.md:79-80`, `asd-dev.md`, `asd-tester.md` link, never restate.
- **AC-1 blocker — `asd-dev.md` has no git tool grant.** Its tool policy limits Run command to `commands.yaml` entries (lint, build, run, dev, custom.*), yet `asd-phase-impl.md:80` instructs every dev to commit. `asd-tester.md:74` was fixed for exactly this contradiction in sprint 006. Any AC-1 delivery must extend `asd-dev.md`'s tool policy the same way — pulling AC-1 into the sync/`canon_hashes` set.
- **AC-2 — the dispatch payload contract never mentions the worktree.** **Single home: `asd-phase-impl.md` step 6 instruction list (`:69-82`)**, one bullet citing AC-1's `git-strategy.md` sentence.
- **AC-3 — no HEAD-verification obligation in either file.** `retro`'s output is explicitly non-durable (`sprint-lifecycle.md:256`), which is why a later sprint must re-verify. **Obligation home: `sprint-lifecycle.md` "Orchestration and adaptive gates" (`:3-9`)**, which already assigns scope writing to the orchestrator; `asd-phase-scope.md:6` implements and cites it. **Recording home is an open choice**: this sprint used both a hand-invented `sprint.md` "Staleness verification" block (`sprint.md:31-42`) and `decisions-log.md:36-40`. `t_sprint.md` has no such section, so mandating it there means a template change; `decisions-log.md` needs none. Pick one — writing both is the double-channel duplication the rules exist to prevent.
- **AC-4 — the interrupted-dispatch contract has no correlated-failure concept.** `review-policy.md:136` frames every attempt per-reviewer; `:140`'s trigger keys on "same reviewer … same manifest digest", so one session-wide cause arms N counters. The count is deliberately not a `state.json` field, so a correlated record must also be a `decisions-log.md` line shape. **Single home: `review-policy.md:132-148`**; both `*-review` workflows already cite it as sole SSoT and must not gain a restatement (`tests/run.js:2988-2993` asserts that citation).
- **AC-5 — the vocabulary lives in prose and code, never in the artefact.** Gaps: (a) the manifest needs a vocabulary field — making it **required** breaks `tests/run.js:2193` `buildManifest` and every fixture at `:2205`, `:2433`, `:2879`; (b) there is no manifest template, so the shape must be defined in `review-policy.md:97` prose and/or as a `runtime.js` emitter — `runtime.js` today only digests and validates, never builds a manifest, so publishing the vocabulary from the validator implies a new code path or subcommand. **Shape home: `review-policy.md:97`. Values home: `.asd/runtime.js`** — one constant shared by validator and emitter, so the two cannot drift.
- **AC-6 — no encoding rule exists, and the lint that "already catches it" is blind after staging.** `code-style.md:139` requires lint to pass before commit; the configured lint (`commands.yaml:5`, `git diff --check`) exits 0 once the damage is staged, so an agent that stages → lints → commits passes a check that cannot see the defect. The rule must name `--cached` (or `HEAD`) or the guarantee is empty. Second problem: `code-style.md` ships to every consumer via `managed_paths`, so "canon is CRLF on disk on this platform" is false for a Linux consumer. **Recommended split: `code-style.md` §19 owns the platform-neutral rule** (anchor a scripted replacement on the file's actual EOL; a whole-file diff for a small edit is the symptom; check before *and* after staging); **`.asd/project/custom-coding-rules.md` owns the repo-local fact**. Caveat: `.asd/project/**` is outside the impl-review change surface, so anything placed there is never reviewed.
- **AC-7 — no `.gitattributes`, and the effective policy is machine-level.** Today's behaviour comes entirely from `core.autocrlf=true` in the system gitconfig; a contributor with `false`/`input` gets different worktree bytes from the same commits. Because every index blob is already LF, `* text=auto` **changes no blob and produces no churn** (`git add --renormalize .` would be a no-op) — it only pins worktree EOL to the platform default, matching today. `* text=auto eol=lf` would instead make the working tree LF on next checkout, which **invalidates AC-6's premise**. The 6 files currently `w/lf` would flip to CRLF under `text=auto`. **Single home: root `.gitattributes`.**
- **AC-8 — an empty external return is governed by nothing.** `review-policy.md:134` scopes the interrupted-dispatch contract to the 4 internal reviewers and defers External Review to `external-review.md`; `external-review.md:35-40` defines a skip only for a preflight/negative-cache failure. A dispatch that passes preflight, starts the wrapped CLI and returns prose with no verdict and no skip (008 `F-8`) falls between the two documents. Nothing requires synchronous completion or forbids backgrounding the wrapped CLI; the `Bash` grant (`:65`) is unqualified and `:102` bounds retries, not asynchrony. **Behavioural home: `asd-external-review.md` tool policy (`:62-69`) + don'ts (`:98-107`)** — await within the dispatch, never background, return the availability skip on inability, empty is not permitted. **Outcome-contract home: `external-review.md`** — exactly two permitted outcomes; `review-policy.md:134`'s scoping sentence points at it so the boundary stops being a hole.
- **AC-9 — no cross-sprint record surface exists in this repo.** `docs/` does not exist; `.asd/project/decisions-log.md` is frozen legacy (`artifact-layout.md:223`); `.asd/project/external-cache.json` is gitignored machine-local and holds only status + retry-after (`runtime.js:100-104`); friction logs and retrospectives are sprint-scoped and archived; `t_decisions-log.md:30` forbids inventing a document type. **`external-review.md` cannot itself hold the data** — it is inside `managed_paths`, so `/asd-update` would copy ASD's own availability history into every consumer.
- **AC-10 — the flag to remove is one clause.** `asd-phase-impl.md:61` is the only place fix-mode parallelism is authorized. `:64` is shared with initial mode and must **not** change — AC-10 is review-fix mode only. Consequential: `:5a`/`:62` routing and `:83` "Wait all task signals" assume a set of concurrent dispatches.
- **AC-11 — no verification obligation on either side.** `review-policy.md:72` says the creator autofixes, full stop; `asd-phase-impl.md:77` allows "or equivalent correct fix" but requires no check against source. **Single home: `review-policy.md` "Autofix vs escalation" (`:70-83`)**, cited by `asd-phase-impl.md:77`.
- **AC-12 — plan format has no reachability declaration.** `sprint-lifecycle.md:298-302` mandates exactly one per-task line (`Material risk:`), typed and parser-critical; `t_plan.md:17` mirrors it. A second mandated line means a matching `t_plan.md` change and a re-read of `:302`'s fail-closed grammar so the two lines' absence semantics do not collide. **Single home: `sprint-lifecycle.md:294-304`**; `t_plan.md` is its declared mirror.
- **AC-13 — the remaining gap is two distinct things, one asserted in place by a test.** (a) *Say it once for both modes*: the property is stated four times, all inside self-hosting carve-outs, and `tests/run.js:3045` asserts exactly four occurrences — de-duplicating requires rewriting that test in the same change. Consumer mode has no statement at all: `external-review.md:53` defines consumer impl-review scope as "changed code and test files" with excludes `.asd/**`, `docs/**`, which reads as an allow-list, leaving `.claude/agent-memory/**` undefined. (b) *Make a mid-sprint memory write reach the reviewed diff*: `review-policy.md:38-40` scopes review to the iteration's diff and `asd-phase-impl-review.md:26` computes it with `git diff` — commits only. A reviewer's own memory write lands after the diff is computed and after the clean-worktree check, and its author cannot commit it (reviewers have no `Write`/`Bash`), while `git-strategy.md:39` bars the orchestrator's counterpart act. Reviewer-authored memory is structurally ownerless and un-reviewable. **Property home: `artifact-layout.md` "Agent memory" (`:85-89`)** — already the cited SSoT, mode-independent; the four restatements become citations. **Diff-reachability home: `review-policy.md` "Change-surface rule" (`:40`)**.
- **AC-15 — nothing in the gate machinery records cost, and the AC names no mechanism.** Gates are keyed by gate name, not by `AC-N`, so "a criterion's running cost" has no existing key, no defined unit (review iterations? fix rounds? hard-gate round trips?) and no measurement point. ## Risks

- **AC-9 as written cannot be delivered literally**: impact=high — putting per-sprint availability observations into `external-review.md` publishes ASD's own operational history into every consumer running `/asd-update`, and `t_decisions-log.md:30` forbids inventing a document type to hold it. mitigation=treat AC-9 as an obligation-statement AC (state *that* availability is recorded across sprints and *where*) and route the storage location through Complication Approval.
- **AC-6 and AC-7 have contradictory premises**: impact=medium — AC-6 asserts "canon is CRLF on disk"; an AC-7 `eol=lf` declaration would falsify it on next checkout. mitigation=decide AC-7 first (`* text=auto` preserves today's behaviour with zero index churn), then phrase AC-6 against it, platform-conditionally.
- **AC-7's target audience is ambiguous**: impact=medium — the 008 retrospective tags the row `consumer`, but the AC text and self-hosting mode only produce a root file *here*. Delivering it for consumers additionally requires a template, an `/asd-init` seeding step (precedent `asd-init/SKILL.md:64`) and a `managed_paths`/README decision. mitigation=settle at plan time; do not let a one-line root file silently expand into an init-surface change.
- **Four ACs land in `review-policy.md`, two in the same section**: impact=medium — AC-4 and AC-14 both rewrite `:132-148`; AC-5 rewrites `:93-105`; AC-11 rewrites `:70-83`. Parallel tasks over one file is exactly the collision AC-10 wants tightened. mitigation=one sequential task chain over that file, ordered AC-5 → AC-4 → AC-14 → AC-11.
- **AC-13 requires deleting content a green test demands**: impact=medium — `tests/run.js:3045` asserts `totalMatches === 4`. mitigation=rewrite the test in the same task, to the owner+citation shape at `:3048`/`:3068`.
- **AC-1 is unfollowable as a rule-only change**: impact=medium — the rule would tell devs to stage precisely while `asd-dev.md` grants them no git command, the exact defect sprint 006 fixed for the tester, and the sprint's own thesis about one-sided obligations. mitigation=pair the `git-strategy.md` sentence with the `asd-dev.md` tool grant plus `sync --apply` and `canon_hashes` in one task.
- **AC-15 has no mechanism, no key, no unit**: impact=medium — without a decided definition of "running cost", any wording added to `checkpoints.md` is unenforceable and unreviewable. mitigation=require a concrete mechanism proposal before the plan admits the task; the honest minimum may be a surfacing obligation at the existing scope-change gate rather than new state.
- **A CRLF rule and a `.gitattributes` change are themselves CRLF-hazardous**: impact=low — every file this sprint edits is CRLF in the working tree, which is how 008's `F-7` arose. mitigation=use `git diff --cached --check` as the standing check for this sprint's own commits.
- **CI does not run the test suite**: impact=low — `.github/workflows/sync-check.yml` runs only `sync.js --check`, so AC-17's green suite is verified locally only. mitigation=noted; expanding CI is outside this sprint's ACs.
