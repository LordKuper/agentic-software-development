### Published guidance (fetched as data per `core.md` "Untrusted-data boundary"; source named per finding)

- **C-1 (Claude Code best practices, "Write an effective CLAUDE.md")** — the file is loaded every session, so each line must answer whether removing it would cause mistakes, and the source's exclude-list names file-by-file codebase descriptions, long explanations and self-evident practices. This repo's `CLAUDE.md` imports `AGENTS.md`, 13.4 KB or about 3.4K tokens, 10.4 KB of it hand-written. E-2 and E-3 fail that test. The same source's include-list names common gotchas and non-obvious behaviour — the class R-1 protects.
- **C-2 (same source)** — emphasis works only when rare; emphasising many lines makes none stand out. The corpus emphasises heavily and uniformly, densest in `asd-phase-impl-review.md` and `sprint-lifecycle.md`. Emphasis inflation is a distinct category from prose bloat and should be named as one.
- **C-3 (cost-optimization guide, "Prompt Audit")** — measured removals: "verify twice" cut cost by a third, "be maximally thorough" saved substantially, and removing contradictory rules and hand-rolled scratchpads gained 7 to 11 accuracy points. Direct hit in canon: the coverage ledger both tells the reviewer to keep reviewing until every row resolves and enforces exactly that deterministically through `validate-ledger`. The enforcement is the check; the exhortation is the priced-out construct.
- **C-4 (cost-optimization guide "Reduce Input Tokens"; cookbook "Move reference material behind tools")** — the cookbook measured 13,462 tokens down to 2,517 by replacing an embedded manual with a lookup tool. ASD already does the tool-shaped version and already scopes it per role. The residual cost is size: one internal reviewer in impl-review reads roughly 72 to 79 KB, about 18 to 20K tokens of rule text, before it sees the diff, and closer to 30K if `sprint-lifecycle.md`'s 49 KB is read whole — nothing in the corpus tells an agent how to read one section without reading the file.
- **C-5 (cost-optimization guide on prompt caching; cookbook byte-stable prefix)** — the review fan-out multiplies C-4: a fresh agent per reviewer per iteration, four internal reviewers plus External Review, so 18 to 20K tokens is re-paid four times per iteration, roughly 220 to 240K tokens of rule text per review phase at three iterations, twice per sprint. An agent body is a byte-stable prefix and caches; rule text arriving as tool results after per-dispatch payload does not. Capturing this conflicts with the SSoT iron rule — see R-8.
- **C-6 (cost-optimization guide, "Effort Parameter")** — below the model's ceiling the highest effort levels pay for depth the task never uses; on knowledge work medium matched default accuracy at 70 to 87 percent of cost while high bought nothing measurable. Seven of nine tier rows are `high`, including all four internal reviewers and all three design creators. Retiering is out of scope absent evidence — recorded as G-8.
- **C-7 (cost-optimization guide, "Advisor Strategy")** — an advisor pairing consulted on nearly every task cost about 2.6 times the frontier model alone for the same result; two to three calls per task is the recommended range. `asd-advisor` is the most expensive family, consulted from cheaper callers, capped at three consults per task. Already compliant; recorded because AC-8 must cover it.
- **C-8 (cost-optimization guide "Output Caps and Format"; cookbook §3)** — output tokens cost five times input; a one-line answer against a five-section memo was $0.49 against $1.40 at equal quality. ASD already shapes reviewer output. The unshaped outputs are the prose artifacts later agents read: `audit.md`, decisions-log entries running 1 to 3 KB of continuous prose, `retrospective.html`. Whether AC-7's rule reaches these is G-6.
- **C-9 (claude-api skill)** — not reachable from the audit dispatch: no Skill tool was exposed to it and no such skill exists in the searched skill roots. The orchestrator, which does hold the skill, ran it at the audit gate; C-10 through C-12 are its findings and G-11 is closed. See [decisions-log.md](./decisions-log.md).
- **C-10 (claude-api skill, effort quick reference)** — the skill's effort vocabulary is `low`, `medium`, `high`, `xhigh`, `max`. `sync.js` validates the Codex side against exactly that vocabulary plus `ultra`, and rejects `ultra` on the cheapest family; the Claude side is validated for nothing. A misspelled or invented Claude `effort` in canonical agent frontmatter is written straight into the generated view, where the host silently ignores it, so the agent runs at the default while canon, the tier matrix and README all claim otherwise. Asymmetric validation of a field both providers carry.
- **C-11 (claude-api skill, effort quick reference)** — `xhigh` sits between `high` and `max`, is described as the best setting for most coding and agentic work on current models, and is Claude Code's own default; `high` is the API default, so every `"effort": "high"` in canon declares the default explicitly. ASD's tier vocabulary uses `high` as its ceiling for Claude and never uses `xhigh`. Whether the dev and reviewer tiers should move is a cost-quality question with no measurement behind it here — recorded against G-8, not proposed.
- **C-12 (claude-api skill, model table)** — confirms the local check: model ids must be the exact rolling strings with no date suffix appended. `.asd/release-manifest.json` `model_families` and `providers.md` hold rolling family aliases only on both providers, and no dated id appears anywhere in canon. ### Where AC-7's rule must live

An economy rule already exists twice, in two scopes, in no canonical home: `AGENTS.md`'s hand-written section, which tells every change to minimise runtime tokens and carries the preserve-list AC-7 needs, but is neither canonical nor shipped to consumers; and `code-style.md` §7, the same principle scoped to in-code comments. Neither is enforceable.

The decisive mechanic: the coverage manifest enumerates every stable reviewer-rubric ID, a verdict omitting a checklist item is INVALID, and no workflow step derives rubric IDs from anywhere except the reviewer agent file's `## Review rubric` bullets. A bullet in `asd-reviewer-documentation.md` is therefore mandatory and non-substitutable under every option; the options differ only in where the rule text lives.

| Home | Reach | Cost of siting it there | Tradeoff |
|---|---|---|---|
| `code-style.md` §7, extended | dev, tester, architect, all four reviewers — but reaches the documentation reviewer in impl-review only, and never ba or ux | none; §7 already carries the germ and the doc-comment rule the reviewer already enforces | its header binds it to code-writing agents during impl and impl-test. Correct here, where canon is code; in a consumer it would not reach `audit.md` or `plan.md` prose and never reaches design-review. Cheapest, narrowest. |
| `artifact-layout.md`, beside the SSoT iron rule | every creator and every reviewer in both phases — the only rule doc on all ten role rows | none; the iron rule already ends with violation equals FAIL from the Documentation reviewer, the same enforcement clause and owner | broadest reach at no extra load. Requires accepting that this file hosts a content rule, which it arguably already does. |
| `core.md`, new section | every role unconditionally | none | `core.md` is the always-loaded hub; an exclusion taxonomy and preserve-list there taxes every dispatch, so the rule would violate itself. Only a pointer belongs here. |
| new rule doc | zero until wired | five mirror edits plus a sync run | a new document type with no template, for one rule — trips the Simplicity Default and the over-engineering checklist. Needs Complication Approval. |
| leave in `AGENTS.md` | this repo only | none | fails AC-7 twice: not canonical, never ships. The line should become a pointer once a canonical home exists. |

Recommendation for the plan phase, not an audit decision: site it in `artifact-layout.md` immediately after the SSoT iron rule, add one rubric bullet to `asd-reviewer-documentation.md`, and reduce `AGENTS.md`'s section and `code-style.md` §7's sentence to pointers. It is the one rule doc every creator and reviewer already loads in both phases, so reach costs nothing; the economy rule and the SSoT rule share an enforcement owner, a verdict class and a failure mode, since the same fact in two homes violates both; and it adds no document, no mirror and no Complication Approval.

## Gaps

- **G-1 (AC-1)** `asd-phase-plan.md` computes no dependency graph, so AC-1's enforcement clause has no step to attach to — either a new step or a re-reading of the criterion. `t_plan.md`'s dependency section is optional, and an ordering rule cannot be enforced from an optional section.
- **G-2 (AC-1)** Wave is undefined vocabulary — zero occurrences in `.asd/rules/**`. It must be defined once before either target can cite it.
- **G-3 (AC-2)** No sibling dispatch in flight is not observable by a dispatched agent: nothing in `state.json` records in-flight dispatches, and transcript-borne context is forbidden. Only the orchestrator can check it, so the agent-facing half must become an unconditional ban with the conditional permission held by the orchestrator alone.
- **G-4 (AC-3)** No canonical definition of the concurrent co-author case. Agent memory is defined as per-agent, so the collision needs its own statement of when two agents co-author one file.
- **G-5 (AC-6a)** The split needs the eight `validate-ledger` rejection classes partitioned into reject-and-re-dispatch against transcribe-and-deviate. No partition exists, and the helper returns failures without a class tag the workflow could branch on — a transcription branch may require the helper to distinguish shape from completeness.
- **G-6 (AC-7)** The rule's scope boundary is undefined: framework canon only, or every artifact an agent later reads. The wider reading reaches every consumer project and would put the constraint into `t_audit.md`, `t_plan.md` and `t_decisions-log.md`. This file is itself in the second set.
- **G-7 (AC-7)** No decision procedure exists for what changes no agent behaviour. Candidates evidenced by this corpus: the removal test from C-1; a provenance test, where a passage traceable to a recorded defect, friction entry or decision is load-bearing; and an enforcement test, where a passage already enforced by a tool grant, a suite assertion or runtime validation is prose-only and cuttable, which is E-4's class.
- **G-8 (AC-8, C-6)** No cost measurement exists for this repo: no per-phase token accounting, no per-agent record, no baseline. Either the sprint accepts that no tier finding can be evidenced, or it defines a minimal measurement — bytes read per dispatch from the role-scoped context rows, as computed in C-4 — as the evidence standard.
- **G-9 (AC-7 enforcement)** The documentation reviewer's rubric bullets carry no stable IDs, yet the manifest must enumerate every stable rubric ID and an omitted checklist item makes a verdict INVALID. The ID derivation is implicit and unwritten — a latent risk for AC-6's ledger work too.
- **G-10 (AC-7 reach)** The role-scoped context table gives the documentation reviewer `code-style.md` in impl-review only. Siting the rule there would leave it unenforceable in design-review; the `artifact-layout.md` option avoids the row edit entirely.
- **G-11 (external input)** CLOSED at the audit gate: the orchestrator ran the claude-api skill itself, producing C-10 through C-12. No unclosed input remains.
- **G-12 (mirror coverage)** The suite machine-checks the phase-chain and agent-count mirrors but not the rule-doc-list mirror, which is why E-3's drift is live and green. Any README-consistent claim rests on human checking for this mirror class.

## Risks

- **R-1 · Cutting load-bearing text under AC-7.** These are long because length is the contract, and the rule must exclude them explicitly: the reviewer verdict token, parsed by both review workflows and the session-start hook, whose per-agent pre-substituted copies remove a substitution step at the point of failure; the ledger row shape and vocabulary literal, validated byte-wise; the `Material risk:` and `Reachability:` line grammars and `t_plan.md`'s parser-critical comment, where a checkbox outside a Task block breaks parsing; the UI-surface and executable-extension enumerations, where the predicate is the list; `code-style.md` §19's EOL and staged-diff paragraphs, each encoding a silent-failure mode with its symptom, the gotcha class C-1 protects; the role-scoped context table, whose length is the mechanism that stops every agent loading all fifteen rule docs; the HTML-shell placeholder mapping and the state-recovery verdict enumeration, where an omitted case is a gate bug; and the APPROVE-latch invariant and the fail-closed per-field default, each stating a case distinction a shorter phrasing collapses.
- **R-2 · AC-7 self-application.** The rule, its taxonomy, its decision procedure and its preserve-list are themselves loaded by every reader of its home file. Written as an essay anywhere, it fails its own test. Cap it at a paragraph plus a short list, sited where readers already pay the file's cost.
- **R-3 · The meta-annotations (E-5) are ambiguous rather than clearly cuttable.** For a reading agent they add nothing beyond the pointer; for an editing agent, the normal case under self-hosting, they are the local signal that stops a pointer being re-expanded into a copy — the exact failure E-1 and E-6 exhibit. Cutting all 66 is a roughly 3 KB win that could regress SSoT within one sprint. Mitigation: classify by audience, and if editor-facing annotations survive, standardise the seven current variants to one short form.
- **R-4 · E-1's fix is a refactor of the two largest workflows.** There is no shared-workflow-fragment mechanism. Hoisting into `review-policy.md` grows the file every reviewer loads in full, worsening C-4 and C-5; inventing an include is a new abstraction, and Codex supports no imports; leaving it duplicated accepts the mirror. Likely the largest single AC-9 change and the one most able to break the review loop.
- **R-5 · `AGENTS.md` edits ripple to every consumer.** The "Rule docs" section is generated; "Architecture" is hand-written below the sync marker. Editing the wrong side either fails to ship or is silently overwritten. Any change requires a clean `sync.js --check` plus the suite's phase-count assertions, which target `AGENTS.md` specifically because it loads on every turn.
- **R-6 · A green suite does not prove an economy edit safe.** The suite asserts file sets, chain mirrors, hashes and engine behaviour, and nothing about prose beyond count words. A deletion removing a real rule passes both the suite and `sync.js --check` — the project decisions log records the same limitation for a prior rename. Mitigation: AC-8 already requires each finding to cite the authority it violates, and AC-9's application should route through the new rubric bullet rather than the suite.
- **R-7 · AC-6b and AC-7 both change the coverage manifest.** A new rules entry and a new field beside `vocabulary` both alter the digested manifest and the ledger a reviewer must resolve; landed in the wrong order, an in-flight review validates against a manifest shape its dispatch predates. The `runtime.js` change goes first.
- **R-8 · Reducing per-dispatch rule reads conflicts with the SSoT iron rule.** The win is real, but every mechanism for capturing it — inlining rule text into byte-stable agent bodies, or slicing rule docs per role — creates second homes for facts. An explicit tradeoff, not something AC-7's rule should authorise implicitly.
- **R-9 · AC-2, AC-3, AC-5b and AC-6a are all dispatch- or commit-contract changes.** Under AC-1's own rule they must precede every task dispatched under them, alone in their wave. Sprint 010 has to apply AC-1 to itself, and the plan phase must be told so explicitly or the ordering is discovered late.
- **R-10 · Sprint 010's own artifacts are inside AC-8's corpus.** `sprint.md`, `plan.md`, this file and `decisions-log.md` are agent-facing text read by later phases. If G-6 resolves to the wider reading, the sprint's own artifacts fall under its own rule mid-sprint. Decide G-6 before `plan`.
