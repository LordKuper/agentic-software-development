Retrospective — Sprint 007 · retrospective-phase

7 entries · 8 actions · 5 systemic proposals · updated 2026-09-07

Outcome

7 entries analysed, 2 consumer actions, 6 framework actions, 5 systemic proposals.

Every entry was recorded by the main orchestrator, which is what the writer mechanism narrowed to mid-sprint. Two entries are recurrences of an earlier entry in the same sprint (F-5 of F-1, F-7 of F-3), so recurrence — not novelty — is this sprint's dominant signal: a correction that lands only in one agent's memory does not survive the next dispatch.

Analysis

EntryRoot causeScope
F-1A read-only agent was dispatched against a repository-wide scope with a rubric requiring it to open many files before concluding anything; the turn budget was spent reading, and no host operation exists to resume a subagent, so the work could only be discarded.asd
F-2A large artifact was composed inline through a shell heredoc rather than the file-write operation; the shell layer imposes quoting constraints the content does not justify.asd
F-3Nothing in the layout rules or in any dispatch payload states where agent memory belongs, so an agent defaulted to the working directory it was given — which was the sprint tree.asd
F-4The documented argument form for the sync step names the canonical path while the tool matches generated view paths, and an unmatched target is reported as success — so following the documentation produces a silent no-op.both
F-5Same cause as F-1, recurring because the first occurrence was corrected by improvising a split rather than by changing the dispatch contract. The phase workflow has no notion of a split review, so the split, the two half-verdicts and their merge were all outside the documented contract.asd
F-6A dispatched reviewer's partial work is persisted nowhere, and the fresh-context-per-iteration rule leaves no checkpoint to fall back on, so any interruption is a total loss rather than a partial one.asd
F-7Same cause as F-3, recurring across a different agent because the first correction was written into one agent's memory and into no rule — and this time the misplaced files were committed, so the sprint tree would have frozen them at archival.asd

Actions

AddressesRecommendationActs onTarget
F-1, F-5Make the split a contract rather than an improvisation: define when a read-only dispatch is too large and how a reviewer's rubric is partitioned, so the halves and their merged verdict have a documented shape instead of being invented after a failure.asd.asd/rules/review-policy.md, .asd/workflows/asd-phase-*-review.md
F-1, F-5Keep sprint scope small enough that one reviewer dispatch covers the diff; a scope that needs splitting to be reviewable is usually a scope that should have been two sprints.consumer<sprint>/sprint.md scoping practice
F-2State that a large artifact write uses the file-write operation, never a shell heredoc — the shell path adds a failure mode the operation does not have.asd.asd/rules/providers.md
F-3, F-7State in the layout rules that agent memory lives at the provider-view root and never inside a sprint tree, and that a sprint folder holds only the artifacts the path map names. A rule is what survives the next dispatch; an entry in one agent's memory is not.asd.asd/rules/artifact-layout.md
F-4Make the tool refuse silently-wrong input: an --apply target that matches nothing should be reported as an error rather than folded into an ok result. The documentation fix below is worth less than removing the silent-success shape.asd.asd/sync.js
F-4Correct the argument wording wherever the sync step is described, including the consumer-facing template, so a fresh project does not inherit the same misleading instruction.asd.asd/templates/t_AGENTS.md, AGENTS.md
F-4Apply the same correction to the project's own coding rules, which carry a copy of the wording.consumer.asd/project/custom-coding-rules.md
F-6Give an interrupted reviewer dispatch a defined outcome: record it as an availability skip for that iteration, the way an unavailable external reviewer already is, instead of requiring a full re-run with no record that the first attempt happened.asd.asd/rules/review-policy.md

Systemic proposals

What would have made this sprint cheaper, read off how it actually ran — three review iterations, forty-two findings, eight implementation dispatches — rather than off the entries above.

ProposalActs onTargetExpected saving
Give implementation dispatches the over-engineering and SSoT checklists that reviewers judge against. The design-time rules already say to apply them proactively during design; nothing says so during authoring. A large share of iteration-1 and iteration-2 findings were prose duplication and restatement in always-loaded files — defects the author could have avoided by knowing the exact checklist that would be run against the text.asd.asd/rules/code-style.md, .asd/workflows/asd-phase-impl.mdReview iterations. Two of this sprint's three were driven mostly by findings of this class.
Check the external-review negative cache before assembling the scope manifest and dispatching the agent, not after. Two iterations paid for manifest assembly and an agent dispatch before discovering an unavailability that the previous iteration had already recorded.asd.asd/workflows/asd-phase-impl-review.md, .asd/rules/external-review.mdOne agent dispatch per iteration while a provider is unavailable.
Say plainly that the orchestrator commits its own bookkeeping at phase exit. Twice a dispatched agent committed orchestrator-owned files it did not author, purely so the next gate would see a clean tree — each time flagging it as a deviation it was unsure it was allowed to make.asd.asd/rules/git-strategy.mdAmbiguity at every phase boundary, plus the commits an agent makes defensively outside its scope.
Distinguish risk-to-the-change from risk-to-the-artifact when the plan declares a task's material risk. Task routing reads that declaration, so in a sprint where every task edits a workflow contract, every task declares a risk and every task routes to the most expensive tier — six of seven here — regardless of how mechanical the edit itself is.asd.asd/rules/sprint-lifecycle.md plan format, .asd/runtime.js routing inputModel cost across a whole sprint's implementation dispatches.
Let a phase state the artifacts it hands to the next one, so a re-entry does not have to re-derive them. Each impl-test re-entry and each review iteration began by rebuilding a scope list and a diff base that the previous phase already knew; the state file records the heads but not the derived sets.asd.asd/templates/t_state.json, .asd/rules/sprint-lifecycle.mdOrchestrator round-trips at every cycle re-entry.
