Retrospective — Sprint 008 · retro-007-remediation

8 entries · 10 actions · 6 systemic proposals · updated 2026-09-08

Outcome

8 entries analysed, 1 consumer action, 9 framework actions, 6 systemic proposals.

This sprint's scope was the sprint 007 retrospective's own two tables, so its first duty is to report on that remediation. Every action 007 named was delivered, but three of its rows were written against a HEAD that had already moved: F-2. More telling, four of this sprint's eight entries are recurrences of classes 007 had already identified — the parallel-dispatch staging hazard behind F-1 and F-3, and the lost-dispatch class behind F-4 and F-8. 007 concluded that "a correction that lands only in one agent's memory does not survive the next dispatch". This sprint's evidence sharpens that: a correction that lands only in a rule does not survive either, when the rule states one half of a two-sided obligation.

The sprint cost six review iterations and roughly seventy findings. Two acceptance criteria did not survive contact: AC-4 was closed at audit as already satisfied at HEAD, and AC-11 was retired at iteration 4 after three fix rounds proved its purpose unreachable by construction. One was added mid-sprint — AC-15, an authorized scope expansion, after a reviewer found the workflow asserting a host guarantee the host does not provide.

Analysis

EntryRoot causeScope
F-1Independent tasks are dispatched in parallel onto one shared worktree and each is told to commit, but no rule states that an agent stages only the paths it authored — so a broad stage sweeps a sibling's in-progress edit into the wrong commit.asd
F-2A retrospective's recommendations are written against the HEAD of the sprint that produced them and carry no recorded verification that they are still unresolved when a later sprint picks them up; 007's own F-4 root cause was itself derived from a stale agent-memory note rather than from current source.asd
F-3The commit-ownership rule added this sprint assigns orchestrator-owned bookkeeping to the orchestrator and forbids an agent committing what it did not author, but neither half covers the converse — an agent that authored a file and did not commit it. Under parallel dispatch agents correctly avoid a directory a sibling is also writing, so those files reliably end up ownerless.asd
F-4The interrupted-dispatch contract treats interruption as a per-reviewer event, but the actual failure mode is correlated: a session-wide limit takes every concurrent dispatch at once, and the split trigger then counts consecutive interruptions per reviewer, escalating five reviewers independently rather than recognising one condition.asd
F-5The per-row-type ledger status vocabulary is stated once, in one sentence of rule prose, and nowhere in the machine artefact the reviewer is handed — so the reviewer must recall it rather than read it off its own input, and the validator that knows the vocabulary is not the thing that supplies it.asd
F-6The read-only property was asserted as an absolute host guarantee while being true only of the artifact surface it was written about: reviewers cannot write artifacts, but memory: project is a separate write channel every reviewer definition grants, and the rule did not distinguish the two.asd
F-7Canon is CRLF on disk on this platform and agents edit it with newline-anchored scripted replacements by default; nothing in the rules says so, and the lint command that catches the symptom reports it as a whitespace error rather than as the encoding hazard it is.both
F-8The external reviewer wraps another provider's CLI whose run can outlast the wrapping dispatch, and nothing requires the wrapper to await it synchronously — so the dispatch can return with neither a verdict nor an availability skip.asd

Systemic proposals

Read off how this sprint actually ran — six review iterations, roughly seventy findings, three fix rounds, one criterion retired and one added mid-flight — rather than off the entries above.

ProposalActs onTargetExpected saving
Fix rounds run sequentially under one agent, not in parallel. The external reviewer observed after iteration 2 that two parallel rounds had each closed their targets while introducing a fresh cross-file contradiction; the three rounds that followed were sequential and introduced none of that class. Parallelism bought wall-clock and cost a review iteration each time.asd.asd/workflows/asd-phase-impl.md review-fix modeA review iteration per fix round — the single largest cost in this sprint.
Require a reviewer's proposed fix to be verified against source before it is applied, not merely applied. Twice this sprint a finding's own prescription was wrong: the ledger-failure arithmetic a finding asked for undercounted, and a corrected memory statement replaced one wrong test name with another. Both were caught only because the dev measured instead of transcribing.asd.asd/rules/review-policy.md, .asd/workflows/asd-phase-impl.mdFix rounds that close a finding while shipping a new false statement.
Make a criterion's reachability part of accepting it. AC-11 survived three fix rounds before anyone traced whether its stated purpose could occur at all; the answer was no, by construction, and each round closed its own finding while leaving the purpose unmet. A plan task whose value depends on two phases agreeing should say which two and on what.asd.asd/rules/sprint-lifecycle.md plan formatThree fix rounds and one retired criterion, in this sprint alone.
Put agent memory in the review surface by default, not by exception. Narrowing the self-hosting exclusion was an action item this sprint; the very next iteration found four false durable statements in one memory file, two of which had already cost a full review re-dispatch each. Memory loads on every dispatch of its agent and had never been reviewed.asd.asd/rules/external-review.md, .asd/rules/sprint-lifecycle.mdRe-dispatches caused by an agent confidently following its own wrong note.
Let a reviewer's verdict be recorded when a late-returning duplicate dispatch contradicts it. At iteration 5 an interrupted external dispatch delivered after its replacement had already returned APPROVE, carrying a verified critical finding the replacement missed. The contract says the interrupted verdict never counts, which is right for bookkeeping and wrong for evidence; the orchestrator had to reason outside the rule to avoid shipping a known-false claim.asd.asd/rules/review-policy.mdThe gap between what the process records and what is known to be true.
Count what a criterion costs, not only whether it is met. This sprint retired one criterion, closed another as already satisfied, and added a third mid-flight. That is healthy, but it happened three times through hard gates because nothing surfaces a criterion's running cost until a reviewer objects.asd.asd/rules/checkpoints.mdHard-gate round trips spent discovering a criterion is not worth its price.
