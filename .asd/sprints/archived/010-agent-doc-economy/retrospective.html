Retrospective — Sprint 010 · agent-doc-economy

5 entries · 7 actions · 6 systemic proposals · updated 2026-09-09

Outcome

5 entries analysed, 0 consumer actions, 7 framework actions, 6 systemic proposals.

This sprint set out to remediate the previous retrospective and to make agent-facing text an enforceable cost surface. It did both, and then spent most of its length discovering that the rule it wrote is harder to apply than to state. Five impl-review iterations produced 23 findings — 13, then 6, then 2, then 2, then none — and the largest single class, a declaration claiming some fact is not restated here while the restatement sits beside it, took six instances across five sites and three fix rounds to converge. Every one of External Review's seven iteration-1 findings was independently verified resolved before the final round, and both remaining reviewers swept the corpus for a seventh instance of that class and found none.

Three of the five friction entries are the orchestrator's own errors, and two of those cost real work: coverage manifests emitted in a shape the validator silently degrades rather than rejects, and those same manifests re-stamped while three dispatches held them. The defect they exposed is now fixed in code, so the shape fails loudly. The third, an instruction that told an agent to do what its own tool policy forbids, is the one worth the most attention — the agent complied and then recorded the practice in its memory as a pattern to reuse, where it survived a round before a reviewer found it.

What the sprint delivered: the ten acceptance criteria, roughly 18.7 KB cut from canon, two silent code defects closed, and a citation sweep that grew from 20 pinned relations to 185 and immediately found two dangling pointers that had survived an earlier release. The suite went 171 to 184, green at the terminal gate.

EntryRoot causeScope
F-1The coverage manifest's n_a is the one field an orchestrator hand-builds per dispatch, and nothing published its shape or checked it — the validator read a nested shape, silently degraded a flat one into "no predicate authorized", and so rejected every truthful row while accepting the malformed manifest that caused it.asd
F-2The manifest is declared immutable to the reviewer but nothing declares it immutable to the orchestrator, so correcting one mid-flight silently invalidated returns that were already correct, and left two different failures indistinguishable in the artefacts.asd
F-3The interrupted-dispatch rule reaches the split remedy only through a second interruption, so a scope already proven too large for one turn must be re-spent in full to prove it again — and the phase never checks scope size before dispatching, though it computes the file list itself.asd
F-4Preflight predicts local executable and authentication state only, never paid-request availability, so a quota-exhausted provider is discovered by spending the dispatch — at whatever iteration it happens to fall.asd
F-5Nothing checks a dispatch payload against the receiving agent's declared tool policy: the orchestrator composes the instruction, and the agent has no way to tell an authoritative instruction from one contradicting its own definition — so a workaround given once became standing guidance in that agent's memory.asd

Systemic proposals

ProposalActs onTargetExpected saving
Audit .claude/agent-memory/** under the documentation-economy rule as its own sprint. Memory is a per-dispatch read surface exactly like canon, it was never in this sprint's AC-8 corpus, and it produced findings in four of five review iterations — including the class that took three rounds to converge. Chasing it file by file inside a sprint scoped elsewhere is unbounded; auditing it once is not.asd.claude/agent-memory/**, .asd/rules/artifact-layout.md "Agent memory"
Have the plan phase size each review iteration's likely scope and say so, so the first iteration of a 56-file change surface is split by design rather than after an interruption. This sprint's first iteration lost a whole dispatch to turn exhaustion and its second ran on a 21-file scope without incident.asd.asd/workflows/asd-phase-plan.md, .asd/rules/review-policy.md
Give the orchestrator a manifest-emitting helper rather than having each phase hand-build one. Every manifest this sprint emitted was assembled inline by the orchestrator, and two of the five friction entries are defects in that assembly; the emitter and the validator should share a source the way the vocabulary and row example already do.asd.asd/runtime.js, .asd/workflows/asd-phase-impl-review.md, .asd/workflows/asd-phase-design-review.md
Let a reviewer's suggested fix be explicitly non-binding in the workflow text, as this sprint's agents already treated it. Three times a creator rejected the prescribed fix for a better one — a hardcoded list derived instead, a qualifier assertion rejected as a wording lock after counter-mutation, a canon-side fix chosen over editing another agent's memory — and each was right. The rule permits it; the dispatch payloads had to say so each time.asd.asd/rules/review-policy.md "Autofix vs escalation"
Prefer deriving a set over enumerating one wherever a test or rule names members. This sprint's two most durable checks both came from that move — the memory-directory sweep derived from the agent roster, and the citation sweep that grew 20 pinned relations to 185 — and the two defects they caught had both survived a hardcoded predecessor.asdtests/run.js, .asd/rules/code-style.md
State that a per-entry suite record is one commit behind the tests that entry added, so only the terminal gate measures the tree that includes them. Four impl-test entries each recorded a run at the tree they analysed rather than the tree they produced, which is correct per entry and misleading in aggregate.asd.asd/templates/t_test-plan.md, .asd/rules/sprint-lifecycle.md "Impacted test set"
