## Risks

- **AC-7 duplicating a checklist that already has a home**: impact=high — `artifact-layout.md`'s SSoT iron rule makes a copy an automatic Documentation-reviewer `FAIL`, and the retrospective attributes most iteration-1/2 findings to this exact defect class, so AC-7 could reproduce the problem it fixes. mitigation=`code-style.md` and `asd-phase-impl.md` carry a link plus applicability statement only, mirroring `design-principles.md` §10's wording; zero checklist items copied. Cheapest route: add the rule doc to `asd-dev`'s `providers.md` "Role-scoped context" row instead of restating anything.
- **AC-1 and AC-6 both editing `review-policy.md`**: impact=medium-high — both insert near the same three sections; sequenced badly they contradict each other on resumption, and both must survive "No dispatched reviewer is ever reused or resumed." mitigation=one plan task, one owner, one insertion point; state the split as *two fresh dispatches over disjoint manifest partitions*, not a resume, so the clean-context rule stands verbatim.
- **AC-6 weakening the review gate**: impact=high — recording an interrupted internal reviewer as `"APPROVE (skipped: …)"` lets an incomplete review satisfy DoD, against "review-incomplete, never as APPROVE" and "an absent key is always blocking". External Review's skip is defensible because the provider is unavailable; an internal reviewer always is available. mitigation=bound it — permitted only after a recorded re-dispatch attempt, never latched, forces re-dispatch next iteration, reason string distinguishable (e.g. `"APPROVE (skipped: reviewer dispatch interrupted, iter N)"`), and requires the decisions-log entry External Review's skip already requires.
- **AC-1 breaking the coverage-ledger gate**: impact=high — `rowsById` rejects any ledger whose row set is not exactly the manifest's, and `coverageManifestDigest` binds one manifest to one ledger, so "two half-ledgers, one manifest" is rejected as review-incomplete. mitigation=partition at the manifest level (each half a complete, digest-bearing manifest over its own subset); assert the union of partitions equals the original row set before merging verdicts, and cover that union property in `tests/run.js` (also good AC-13 material).
- **AC-10 altering routing for consumer projects mid-version**: impact=high — `routeTask` fails closed on an unrecognised input shape, so a stricter `risks` schema blocks every dispatch in a consumer still emitting the old string array; and loosening `hasRisk` silently downgrades security/migration/contract work that routes `critical` today. mitigation=accept both shapes (a bare string keeps today's critical semantics; only an explicitly-typed risk-to-artifact entry may route lower), never remove an existing risk class from `providers.md`'s critical list, keep `priorTier`'s no-downgrade clamp, cover both shapes in tests. Bump SemVer and add a migration if any persisted `state.json.task_routing` shape changes.
- **AC-11 changing the state schema against sprints in flight**: impact=medium — a consumer mid-sprint has no such field; a reader assuming presence crashes the resume path, and `.asd/hooks/session-start.js` must keep failing silently. mitigation=copy the two documented precedents verbatim (`iteration_heads`' absent-key fallback; `latched`'s "wholly absent object == `{}`, never an error"), state the fallback in the same paragraph shape, and keep the field purely an optimisation — re-derivable, never a gate input.
- **Cross-file consistency breakage**: impact=medium. (a) README folder map needs an `agent-memory/` line if AC-3 lands; (b) `core.md` "See also" is a no-op unless an AC adds a rule doc — if one does, it must also reach `t_AGENTS.md`'s rule-doc list, README, and `managed_paths`; (c) `canon_hashes` self-heals via `--apply` but goes stale on any canon edit not followed by it — `tests/run.js` catches this, and it has recurred repeatedly; (d) `providers.md`'s routing prose must move with any AC-10 `routeTask` change.
- **AC-5's edit target is outside both the write allowlist and the review surface**: impact=medium — `.asd/project/custom-coding-rules.md` is not in the self-hosting allowlist, and `.asd/project/**` is in `external-review.md`'s self-hosting `exclude_paths`, so the change is both hard to authorise and invisible to impl-review. mitigation=call it out in `plan.md` as an explicitly authorised out-of-allowlist edit, and verify it by grep in the plan's verification task rather than relying on review coverage.
- **AC-3 contradicting the read-only-generated-view rule**: impact=medium — three canonical files state `.claude/` is read-only always; naming `.claude/agent-memory/` as a legitimate write target without a carve-out creates a conflict a reviewer will correctly flag. mitigation=phrase the carve-out once in `artifact-layout.md` and link to it from where the read-only rule is stated; do not restate it in `asd-dev.md` or `asd-phase-impl.md`.
- **AC-2 over-reaching into External Review**: impact=medium — `external-review.md` mandates a here-string piping the prompt into the wrapped CLI's stdin precisely because the agent is read-only and nothing may touch disk; a blanket "never a shell heredoc" invalidates it. mitigation=scope AC-2's rule to *writing an artifact to disk* and name the stdin-pipe case as out of scope in the same sentence.
- **Two ACs already satisfied, so the sprint may generate churn**: impact=medium — re-implementing AC-4 risks regressing a working fail-closed path; re-implementing AC-13's minimum adds a third assertion of what is already asserted twice. mitigation=reduce AC-4 to the `orphan-unmarked` residual (or close it as satisfied with a decisions-log entry) and re-point AC-13 at the genuinely new behaviour of AC-1/6/10/11.
- **`tests/run.js` section-number collisions**: impact=low — `// 7.` and `// 15.` each appear twice. mitigation=append as `// 19.`, leave existing numbering alone.
