# Audit

## Scope reference
[sprint.md](./sprint.md)

Docs-side audit for a **framework-internal revision sprint**. There is no feature to scan for pre-existing product documentation: this repo IS the ASD framework (`AGENTS.md`, "What this repo is"), ships no application code, and has **no `docs/` directory on disk** (glob-confirmed) because its self-hosting profile disables `prd`/`ux_spec`/`adr`/`c4`. The audited corpus is therefore the framework's own artifact *definitions* — the 34 templates under `.asd/templates/`, the 13 rule docs that mandate them, the 10 phase workflows that produce and consume them — plus the one completed sprint (`001-rename-design-to-docs`) as the only empirical sample of what those definitions actually produce.

This document adds one sprint-specific top-level section, **"Artifact axis verdicts"**, which satisfies AC-1. AC-2 (phase axis) and AC-3 (agent axis) are the Architect's companion sections.

`documents.prd` and `documents.adr` are `false` in this sprint's frozen `state.json`, so no `<sprint>/design/prd.html` or `adr.html` draft was produced — per `asd-phase-audit.md` step 5, a disabled document is never draft-created in audit and its finding stays as migration-plan/verdict text instead.

## Existing docs found

No product documentation exists anywhere in this repo, in any format or location: no `docs/`, no wiki/Confluence/Notion export, no RST/DOCX/PDF, no README outside root. The relevant existing documents are the framework's own artifact contracts. Quoted here because every verdict below is scoped against one of them.

- [`.asd/rules/artifact-layout.md`](../../rules/artifact-layout.md) — **SSoT for the entire artifact axis.** Declares both path trees, the optional-document rule, the provenance model, the **"Single Source of Truth (iron rule)"** ("Each fact has exactly one home file. Other files link to it, never copy. Violation = `FAIL` from Documentation reviewer"), the **"Document responsibility"** frontmatter contract, the mandatory **"HTML shell wrapping"** rule ("Every user-facing HTML artifact … MUST be wrapped in `t_html-shell.html`"), and the ownership of `manual-steps.md`, `test-plan.md`, `tech-reference/`, and the decisions log. Any artifact-axis change starts here.
- [`.asd/rules/sprint-lifecycle.md`](../../rules/sprint-lifecycle.md) — the **phase → artifact production table** (lines 46–57) and "Optional documents", which already implements one axis of artifact reduction: `documents.<name>` flags, frozen at `scope`, with the "No-op phase rule". Also fixes the never-optional set: "Never optional: `sprint.md`, `state.json`, `plan.md`, `test-plan.md`, impl-review reports, `manual-steps.md` (already lazy), `.asd/project/decisions-log.md`, `stubs.md`."
- [`.asd/rules/checkpoints.md`](../../rules/checkpoints.md) — the gate table. Binding constraint on this axis: sprint.md's Out-of-scope forbids "any reduction that removes a user approval gate … without explicit user sign-off". Also: "A no-op phase … satisfies the next phase's precondition via its `COMPLETED` signal alone."
- [`.asd/rules/review-policy.md`](../../rules/review-policy.md) — **"Coverage ledger (mandatory — blocks verdict)"**: "every file in review scope listed once … every item in this reviewer's checklist … listed once", and the enforcement rule: "the dispatching phase workflow validates each internal reviewer's ledger — **read from the reviewer's returned text, before that text is written to the review file**". That parenthetical is the hook that makes verdict A-13/A-14 possible without weakening the gate.
- [`.asd/rules/external-review.md`](../../rules/external-review.md) line 49 — the framework's own precedent for dropping derived renders: **"Generated output never enters any payload. Excluded everywhere: `**/dist/**` (likec4 build), `design-system.html`, `architecture.html` — all derived from a source the reviewer already sees (`*.c4`, `DESIGN.md`, `subsystems.yaml`). Review the source, not the build."** ASD already classifies three of its own mandated artifacts as pure build output, yet still mandates agents author and regenerate them.
- [`.asd/rules/design-system.md`](../../rules/design-system.md) §1 and §10 — "`docs/ux/DESIGN.md` = SSoT for tokens, components, states, theme rules", and the 7-step add/edit process whose step 4 is "Regen `design-system.html`" — i.e. a mandated full re-render on every token change.
- [`.asd/templates/`](../../templates/) — the 34 structural contracts themselves. The ones with the largest mandated surface: `t_html-shell.html` (**232 lines**, inlined into every HTML artifact), `t_design-system.html` (107 lines, of which the token-reference dump and UI-composition preview are marked "Mandatory"), `t_accessibility.html` (9 sections), `t_review.md` (findings + two-part ledger + verdict + next action + escalations + manual verification), `t_audit.md` (11 sections, 5 marked optional), `t_test-plan.md` (7 sections).
- [`.asd/sprints/archived/001-rename-design-to-docs/`](../archived/001-rename-design-to-docs/) — **the only empirical evidence in the repo.** Its `audit.md` (262 lines), `plan.md` (195), `test-plan.md` (73) and 24 review files are the measured basis above. Its review files are also the direct evidence for the ledger finding: `iter-01/quality.md` is 119 lines of which 79 are no-finding ledger rows; `iter-01/documentation.md` 115/65; `iter-01/performance.md` 124/59.
- [`.asd/project/decisions-log.md`](../../project/decisions-log.md) — 161 lines, append-only. Entries from sprint 001 run to essay length (the `pr`-phase entry at line 140 is a single ~600-word bullet). Its last entry (2026-09-01, "FOLLOW-UP (framework gap, not fixed)") already records one artifact defect this sprint can close: "`archived_at` is written by `asd-phase-pr.md` merge-mode step 3 but appears in neither `.asd/templates/t_state.json` nor `.asd/rules/sprint-lifecycle.md` 'State recovery'".

- **G-10 (code side, needs a rule sentence): no rule says who writes `state.json`.** The workflows disagree — `asd-phase-design-review.md` step 4 and `asd-phase-impl-review.md` step 2 write it inline; `asd-phase-audit.md` step 7, `asd-phase-design.md` step 5, `asd-phase-plan.md` step 4, `asd-phase-impl.md` step 4 and `asd-phase-impl-test.md` step 1 delegate the same write to `asd-pm`. `sprint-lifecycle.md` "State recovery" says only that state is "updated on every phase transition" and names no writer. - **G-11 (needs user decision — blocks P-3): what `state.json.phase` becomes when three phases are skipped in one write.** `sprint-lifecycle.md` line 77 specifies that a no-op phase "appends **its own** phase name to this array in the same write that advances `phase`" — a one-phase-at-a-time contract. This matters because `session-start.js` computes the next phase mechanically as `PHASE_CHAIN[idx+1]` (lines 82–84): if the collapsed write leaves `phase: "design"`, a resumed session reports next = `design-review` and re-enters the collapsed block. **Recommended resolution**: the collapsed write sets `phase = "design-promote"` (the **last** collapsed phase, so `nextPhase()` yields `plan`) with all three names in `skipped_phases`, and `sprint-lifecycle.md` line 77 gains the multi-phase case explicitly. - **G-12 (needs a schema slot — blocks P-9): a scoped-out reviewer needs a recorded skip, not an absent key.** Today `state.json.reviews.impl.verdicts["iter-NN"]` holds one key per dispatched reviewer, and `asd-phase-pr.md` step 4 parses verdicts "for the reviewers actually required this sprint". - **G-13 (code side): no phase- or agent-axis change in this sprint is machine-verifiable.** `tests/run.js` covers only `.asd/sync.js` / `update.js`; `sync.js --check` sees canon→generated drift for `agents`/`skills`/`hooks` but **not** for `rules`/`templates`/`workflows`, which have no generated counterpart (established in sprint 001's audit, G-10 there).
