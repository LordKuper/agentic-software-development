# ASD Workflow: Impl Test

Owner: inline orchestrator; dispatches `asd-tester` for strategy, `asd-tester-runner` for area runs, a suite gate with no test change or smoke, plus a memory hit's owner and `asd-advisor`. Step 2a can close a verified prose-only re-entry inline.

## Entry
```json
{"requires": ["active sprint at .asd/sprints/<NNN-slug>/", "impl COMPLETED received (build + lint green); state.json.phase advanced from impl", "state.json.review_fixes_pending and test_defects_pending both cleared by the impl fix-mode finalize"], "modes": {"entry-1": "test-plan.md has no Entry log row (first entry this sprint)", "re-entry": "a prior Entry log row exists; its HEAD analysed is <prior-sha>", "resume": "the last Entry log row has an empty HEAD analysed (interrupted current entry, e.g. a stalemate halt)", "suite-revision": "a tester dispatch mode of step 9a: the accepted sprint.md scope asks for a suite revision and test-plan.md `## Suite revision` holds no area or a pending one"}, "ops": ["context: node .asd/runtime.js context --phase impl-test --role orchestrator at entry, read it; --role <agent> before each agent delegation in ## Dispatch, passed as inputs.context, each Conditional grant whose condition holds named in inputs; --out per agent-protocol.md 'Dispatch payload'", "append friction: F-N to <sprint>/friction-log.md per sprint-lifecycle.md 'Friction log'", "timing: a dispatch op around each tester dispatch, whose payload timing key carries <sprint>/timing.jsonl and that dispatch id, the suite ops' --parent (sprint-lifecycle.md 'Operation timing')"]}
```

## Inputs
```json
[".asd/project/config.yaml", "<sprint>/state.json", "<sprint>/plan.md", "<sprint>/test-plan.md", "persistent docs per sprint-lifecycle.md 'Input sources' (requirements, ux, contracts)", ".asd/project/commands.yaml", "custom-common-rules.md, custom-coding-rules.md", "existing test sources"]
```

## Steps

Autonomous: no user gate on a green impacted-set run, none on routing defects back to impl short of a stalemate. A single base tester owns strategy and authoring per entry and never resumes into a later entry. Allow one plan writer at a time, including the orchestrator. After session loss recover from `test-plan.md`, not an agent's transcript.

1. Read `.asd/project/config.yaml` (`language.chat`, `language.docs`, `backward_compat`, `self_hosting`, `safety_valve`), `<sprint>/state.json` → write `phase=impl-test` inline (mechanical, no gate). Detect the mode per `## Entry` `modes` from `<sprint>/test-plan.md`'s `Entry log`. **Resume**: keep its row (step 4 appends none), take `<prior-sha>` from the row before it (none → entry 1, amended not rewritten), never re-append its `D-N` rows; when they exist and a current answer (step 9) names their digest, go straight to step 9's current-answer branch. Entry 1 of a sprint that removes a mechanism or term also runs the leftover-term check `artifact-layout.md` "Agent memory" requires, in the strategy pass (step 4), its memory hits fixed at step 7a
1a. `asd-tester` is unrouted (`providers.md` "Task-class variants and routing"): no `route-task` call, no `task_routing` record. At each dispatch pass the role's payload (`agent-protocol.md` "Dispatch payload", `## Dispatch`) and append `- YYYY-MM-DD — route <taskId>: <standard|runner>, dispatch HEAD <sha>` (`git rev-parse HEAD`). Area runs use the entry's task id and a unique dispatch id; the area and stage travel in `inputs.area`.
2. **Change surface**:
   - **Entry 1**: run command for `git diff <git.base_branch>...HEAD --stat <pathspec>` plus file list, the pathspec excluding the impl-review row's exclusions (`.asd/rules/external-review.md` "Phase-scoped payload"). This is the **full change surface**; a `Test-only` Task's commits (trailer `ASD-Task: Task N`, `sprint-lifecycle.md` "Plan file format") are existing tests in it
   - **Re-entry**: run command for `git diff <prior-sha>...HEAD --stat <pathspec>` (same pathspec) — the review-fix or test-fix commits made since the prior entry. This **delta** is the scope for steps 4 and 7 only
   - Either way: derive the **impacted set** per `sprint-lifecycle.md` "Impacted test set" (diff test files + reference/import search + AC-tag search, native selector override when `commands.yaml` carries one, the shared-infrastructure safety valve applying to step 8's suite gate only) — the scope for steps 3 and 8
2a. **Prose-only review-fix re-entry** — before dispatch, confirm `impl` finalized a review fix, then read every changed hunk and search for readers of the changed paths, headings, anchors and text in tests, fixtures, runtime and CI. Trace discovery globs, shared loaders and text extracted indirectly. Qualify only when the search demonstrates ordinary prose with no parsed content or executable effect, no pending test work (including removals, stubs and suite revision), and a complete named selection of affected contract areas under the safety valve. Run the named contract areas (in this repo `node tests/run.js <area>…`), lint and build, bracketing test runs per "Operation timing". If any eligibility condition is uncertain or any check fails, take the normal tester route with the results. On green, rotate and append the re-entry as in step 4, preserving an interrupted row; record the search paths, terms and selection in `Risk → check decisions` with decision `none`, record `Suite run` for the verified revision, then handle smoke inline and close per step 10.
3. **Pre-strategy impacted run** — run the impacted existing tests; the raw result feeds strategy. Default: the base tester runs it. On a large first entry, split only when existing named runner areas map independently to the change surface and their disjoint selections together cover the impacted set. Include cross-area tests explicitly in that coverage; use the ordinary run if selection or isolation cannot be shown. The orchestrator seeds `Area runs` in a committed plan shell before the first run. Run areas serially via fresh runners (`mode: area-run`); supply the stage, exact command, relevant path set (source, tests, dependencies and runner setup), and area in `inputs.area`. Each runner commits that row's result before returning. Finish the runs before strategy; include failing tests in the evidence.
4. **Strategy pass** — the tester receives change surface, prior plan evidence, ACs, contracts, commands and rules (`## Rules`), and:
   - **re-entry**: first rotates the previous entry's narrative rows, review-fix rows included, into `test-plan.entry-NN.md`, leaving each struck `Removed tests` row (step 9a) live (`artifact-layout.md` "Test plan"), then writes each review-fix removal request from the rotated `Risk → check decisions` rows as a live `Removed tests` row, which step 5 collects; analyses only the delta — the material risk introduced or changed by the fix commits; leaves prior `Risk → check decisions` rows untouched unless a fix actually changed that risk's behaviour, in which case it supersedes a rotated one
   - **entry 1**: writes `<sprint>/test-plan.md` per `t_test-plan.md` (Risk → check decisions etc.), preserving any step 3 shell and its evidence. Leaves the first `Entry log` row's `HEAD analysed` unfilled (scope = "full change surface") and proposes each `temporary(<NNN>): ` test of an earlier sprint (`<NNN>` below this sprint's number) as a `Removed tests` row, reason `temporary: sprint <NNN>`, which step 5 splits like any removal. **Re-entry**: amends it — appends new/updated rows, the new `Entry log` row's `HEAD analysed` left unfilled (scope = "delta since entry N-1"); never rewrites prior rows outside the ones actually revised. Emits COMPLETED. The `HEAD analysed` sha is written at step 9's routing exit or in step 10, after the prune/author commit (step 7) and the suite recording (step 8) — never before — so the next re-entry's delta excludes this entry's own test-authoring commits
5. Read `test-plan.md` → collect proposed removals; split into in-scope (test file inside the change surface) and out-of-scope — outside the sprint's **overall** change surface, not merely the current delta
6. **Removal gate** [GATE adaptive: test removal] — only when out-of-scope removals exist: apply `checkpoints.md`; strict requests the user's explicit approval, adaptive needs recorded authority/evidence. A rejected removal becomes a struck row (step 9a).
7. **Prune + author pass** — the tester handles every independent area serially, scope the set step 4 analysed:
   - deletes the approved removals; writes the `add` decisions at the chosen level, never re-authoring a `Test-only` Task's tests (strategy and pruning still cover them); admission (gap proof), fail-first regression proof and test-quality bars per `code-style.md` §17 (SSoT) — the gap proof and the regression proof recorded in the `Added tests` row
   - **entry 1**: resolves each stub a `plan.md` `Stub <ref> → impl-test` line routes here (`sprint-lifecycle.md` "Plan file format") per `git-strategy.md` "TODO stubs": its TODO resolved in the test file, its `.asd/project/stubs.md` row deleted
   - commits per Conventional Commits; emits COMPLETED
7a. **Memory fix** — before step 8, each hit in `.claude/agent-memory/<owner>/` the tester reports (step 4's leftover-term check, step 9's memory class) goes to its owner's memory-fix dispatch in this entry (`review-policy.md` "Memory-fix dispatch"), never a `D-N`.
8. **Suite gate** — choose scope per `sprint-lifecycle.md` "Impacted test set" (including the safety valve). **Reuse first**: an eligible earlier green `Suite run` counts; record its `HEAD` in `Suite run` and the decisions log. For a split first entry within impacted scope, recompute the selection after test changes and run it area by area as in step 3, using separate `suite` rows. After all required results are current, the orchestrator runs lint/build and writes the aggregate `Suite run` with commands, exit results and verified `HEAD`. If full coverage is required or the split is no longer evidenced, run one suite gate. The base tester runs it after changing tests; otherwise a fresh `asd-tester-runner` runs it. Any red gate goes to the base tester for step 9 triage. Verdict per `## Rules` suite gate.
9. **Triage** on any failure:
   - **AC deviation with no failing test** (the tester found the implementation departing from an AC-N while no test fails) → a `D-N` row, `Failing test: none (AC-N)`, `Symptom` naming the AC and the deviation, never rated acceptable; routed as a code defect below
   - **test defect** (bad assertion, wrong fixture, flaky pattern) → re-dispatch step 7 for the offending tests, then step 8 again
   - **code defect** → append a `D-N` row per `t_test-plan.md` `Defects` (`Entry` = this entry, status `pending`); run command `node .asd/runtime.js defect-stalemate --plan <sprint>/test-plan.md` (detection shape only from `external-review.md` "Stalemate detection"). **Stalemate** [GATE hard: stalemate]: two consecutive entries routed the same code-defect identity set — a green entry between them breaks the run; identity is the `Defects` file path, runner failure line and failing test, never `D-N`; `impl-review` rows never count; the command compares deterministically:
     - a **current answer** is a decisions-log stalemate answer naming this `digest` and appended after the log's last routing line naming it; an earlier answer is spent — it covers only the next routing of that set, and the same set repeating after it escalates again
     - `stalemate: true` and no current answer → emit `FAILED: stalemate <digest>` instead of routing and, after an escalation consult, request a hard user decision (`checkpoints.md`): continue test-fix with guidance, accept as debt, or abort; append the answer with the digest to decisions-log, then apply it
     - `stalemate: true` and a current answer → apply it without re-asking: continue → route below, its guidance riding the test-fix payload; accept as debt → set those rows `accepted-debt`, register each failing test in `.asd/project/stubs.md` with an `(accepted-debt)` Reason, re-dispatch step 7 to skip exactly those tests, then step 8 again; abort → ABORT
     - otherwise, or on continue, **route**: close the entry with `node .asd/runtime.js impl-test-close --test-plan <sprint>/test-plan.md --entry <N> --decisions <sprint>/decisions-log.md --line "impl-test: defects <D-N list> → impl test-fix (digest <digest>)"`, which fills this entry's `Entry log` `HEAD analysed` with the current HEAD and appends the decisions-log line (mechanical, no gate). Handle any refusal per `Rules`. After a successful close, write `state.json.test_defects_pending = true` inline; commit these bookkeeping writes (`sprint-lifecycle.md` "Impl-test commits its own output"); emit COMPLETED with `NEXT: impl`
   - **memory defect** (the failure traces to text in `.claude/agent-memory/<owner>/`) → step 7a, then step 8 again
   - several kinds present → fix the test and memory defects first, re-run, then route the remaining code defects back
   - no iteration cap: loop until the impacted set passes; an unfixable state surfaces as a dev/tester `FAILED`, never a silent exit
9a. **Suite revision** — only when step 8 is green, the accepted `sprint.md` scope asks for a suite revision and `test-plan.md` `## Suite revision` holds no area or a `pending` one: dispatch a fresh `asd-tester` in `suite-revision` mode (route line as step 1a), which follows `asd-tester.md` "Suite revision" (a removal the accepted scope item covers, by area and removal criteria, cites that item with no step 6; any other out-of-scope removal is written as a proposed `Removed tests` row, never deleted, its area staying `pending`), sets the areas it finishes to `done` and commits. Before each further dispatch apply step 6's gate over those proposed rows: that dispatch deletes the approved ones; a rejected one stays in `Removed tests` as a struck row (`~~<file:name>~~`, never rotated) recording the rejection by test identity, which no later dispatch proposes again and step 5 does not collect. Dispatch again until no area is `pending` — the ledger is the only hand-off, an interrupted revision resumes from it — then step 8 over the revised tree.
10. **Green impacted run** — first, when `commands.yaml` carries `smoke` (absent → skipped), a fresh `asd-tester-runner` runs it once (inline for step 2a) and records `Smoke: <command> — pass|fail` in `Suite run`; a fail goes, as in step 8, to a fresh base `asd-tester`, which appends the code-defect `D-N` row (`Failing test: none (smoke)`, `Symptom` the first failure line) and routes it per step 9's code-defect branch instead of closing green. Then the manual-verification check (`artifact-layout.md` "Test plan" Manual verification): each `Manual verification` row gets it once, at the first entry whose suite gate is green after the row is written — request a user decision (pass / fail, with notes) for each row still lacking a result, record each as `result: <pass|fail> — <notes>` beneath its row (impl-review reads it there), and append one decisions-log line. Then close the entry (mechanical, no gate) with `node .asd/runtime.js impl-test-close --test-plan <sprint>/test-plan.md --entry <N> --decisions <sprint>/decisions-log.md --green --base <git.base_branch> --line "impl-test: impacted set green (<counts>), <added>/<removed> tests"`, which also records `Line delta` in `Suite run`, fills this entry's `Entry log` row `HEAD analysed` with the current HEAD and appends the decisions-log line; a refusal is repaired per `Rules`; confirm `test_defects_pending` null; commit these bookkeeping writes (`sprint-lifecycle.md` "Impl-test commits its own output") and the timing ledger — `git status --porcelain` MUST be empty before this step's COMPLETED; emit COMPLETED with `NEXT: impl-review`
11. tester `QUESTION` or FAILED → escalation consult, then `agent-protocol.md` "Relay"; ABORT → relay, halt; no signal → `sprint-lifecycle.md` "State recovery" failed dispatch before re-dispatch
12. On `ADVICE_NEEDED` from the tester → relay per `agent-protocol.md` "Relay"; execution resumes, no halt.

## Rules
- must: select the test approach only after the implementation exists, against the real change surface — never speculatively from the plan, a `Test-only` Task's declared paths included; authoring bar, check-ladder selection, prune criteria, no-new-test decision rule (decision `none` with its reason in `test-plan.md` when no test qualifies) and fail-first regression proof: `code-style.md` §17 (SSoT), binding here.
- must: run the existing impacted tests before selecting anything new (step 3), so the strategy observes actual post-impl behaviour and catches an `impl` regression before any new test is authored. A `Test-only` Task's commits are existing tests in entry 1's change surface: the pre-strategy run covers them, entry 1 never re-authors them.
- must: resume a split first entry from committed area rows. Keep a result only with the same stage, command and relevant paths, its `HEAD` still an ancestor, and no changes in those paths or their shared infrastructure from that `HEAD` through the current worktree (including staged or untracked files). Redispatch missing or invalid evidence; uncertain path coverage requires the ordinary run. Check the rows again before aggregating step 8. Individual area rows never satisfy `Suite run` reuse or the terminal gate.
- must: re-entry — scope strategy and prune to the delta since the prior entry (`Entry log`), not the whole change surface; amend `test-plan.md`, never rewrite it, after rotating the prior entry's narrative rows (`artifact-layout.md` "Test plan").
- must: `Defects` rows persist across entries — a resolved row stays `fixed` for the record; a reappearing defect gets a new `D-N` row, never a reopened one.
- must: record a reason for each in-scope removal — a redundant one reads `redundant: survivor <file:name>, branch <what it exercises>`, naming the surviving test; a removal outside the sprint's overall change surface passes step 6, save a step 9a removal the accepted scope item covers; an uncovered step 9a one is a proposed `Removed tests` row, its area staying `pending`, which 9a gates with step 6's gate before the next dispatch deletes it.
- must: suite gate — every entry records a run or eligible reuse from the runner's exit code and report. Use the impacted set and its safety valve at this gate (`sprint-lifecycle.md` "Impacted test set"). The terminal `impl-review` gate still requires full-suite evidence.
- must: at step 9 or 10, every `impl-test-close` validation refusal returns `{"refusal":{"file":…, "check":…, "cause":…}}` before writing the plan or log. Pass that object as `inputs.refusal` to a fresh base `asd-tester` (`mode: close-repair`), with `write_scope` limited to the named file. This covers `Entry log` and `Suite run` in the live plan and `Added tests` in the live plan or the immediately prior rotated segment. The tester makes the smallest repair supported by existing evidence. An `Allowance` names risks from `Risk → check decisions`. After COMPLETED, retry the same close command with the same run and manual-verification evidence. A command failure with no refusal object goes to step 11 as FAILED.
- must: triage a failure as a test defect (fix it, re-run), a memory defect (report it, step 7a) or a code defect (a `D-N` row, never a production-code fix) — an AC deviation found with no failing test included.

## Dispatch
```json
[{"agent": "asd-tester", "when": "steps 3-7 when applicable; step 8 after it changed a test and no split applies; step 9 on red; step 9a; a step 9 or 10 close refusal", "payload": ["mode", "task", "inputs.context", "inputs", "write_scope", "language", "timing"], "signals": ["COMPLETED", "QUESTION", "ADVICE_NEEDED", "FAILED", "ABORT"]}, {"agent": "asd-tester-runner", "when": "each split area at steps 3 or 8; single step 8 gate when step 7 changed no test; step 10 delegated smoke", "payload": ["mode", "task", "inputs.context", "inputs", "write_scope", "language", "timing"], "signals": ["COMPLETED", "FAILED", "ABORT"]}, {"agent": "<owner> of .claude/agent-memory/<owner>/", "when": "a memory hit (Claude only), step 7a", "payload": ["mode", "task", "work", "inputs.context", "write_scope"], "signals": ["COMPLETED", "FAILED"]}, {"agent": "asd-advisor", "when": "ADVICE_NEEDED relay; escalation consult before a user escalation (agent-protocol.md 'Relay')", "payload": ["turn_budget", "inputs.context", "question, options, context paths"], "signals": []}]
```

## Signals
```json
{"QUESTION": "blocker: AC behaviour genuinely ambiguous, or a Simplicity Default trigger (new test dependency or test infrastructure) needing Complication Approval; step 11", "FAILED": "blocker: test runner broken; step 11; tech-reference missing: orchestrator writes it (`artifact-layout.md` 'Tech reference docs')", "FAILED: stalemate <digest>": "emitted by this workflow at step 9, a hard decision"}
```

## Exit
```json
{"writes": ["<sprint>/test-plan.md, test-plan.entry-NN.md (re-entry)", "tests in repo", ".asd/project/stubs.md (accept-as-debt)", "state.json", "commits", "decisions-log.md"], "next": [{"if": "impacted set green", "next": "impl-review"}, {"if": "code defects route to impl test-fix mode", "next": "impl"}]}
```
